ep04 的 v5/v2 只是冻结兼容分支，继续服务旧实例；它不代表新流程，新实例不得参照。

03 · Upstream Outputs

三份上游正式内容产物

真正同步给下游作为内容输入的只有这三份。其余报告只用于治理与验收，不是章节创作素材。

01 内容输入 approved-spoken-text.txt

用户明确批准的连续口播。决定整集「实际说什么」，是 A-page Nx 的唯一来源。

02 内容输入 episode-XX-a-page.json

每页的批准口播 Nx、screen guidance、evidence / relations 与静默约束——下游屏幕表达的方向与事实边界。

03 内容输入 episode-XX-visual-rough.md

用户批准的视觉粗设，决定页面配方、G/R/M 结构、媒体需求和关系载体。

治理 · 验收 episode-XX-a-page-validation.json

A-page 机器验证报告：coverage、unresolved、failures。

治理 · 验收 episode-XX-visual-rough-validation.json

visual rough 验证报告，用于批准前的结构核对。

narration-brief.json 与 compile trace 属于过程文件，留在 .tmp/narration-pipeline/，不进 Git，也不进入 inputs/。
04 · Repo Routing

单仓双域与目录路由

单一 Git 根，两个清晰的工作边界。播放器实例只消费 inputs/，不得反向修复或覆盖任务包。

01 事实源 · 只读 narration-pipeline/episodes/

51 集任务包事实源、口播、A-page v6 与 visual rough v3 的权威技能域。任务包保持只读。

02 过程文件 · 不进 Git .tmp/narration-pipeline/

brief、草稿口播、编译追踪等上游过程文件目录，不是事实源，不提交 Git。

03 正式消费入口 player/episodes/<id>/inputs/

上游批准 handoff 的唯一正式入口。只有经过批准和验证的正式文件才能发布到这里。

04 章节实现 player/episodes/<id>/src/

章节代码、narrations.ts 与封面；51 期标准封面内容库位于 episodes/_shared/covers/。

下游分为两个阶段：Phase 1 读取 inputs/ 正式输入做计划，Phase 2 按 A 发放三源 handoff，章节 Agent 重新创作完整上屏内容。

PHASE 2

按 A 发放三源 handoff

.handoffs/Axxx.json 每个 A 一份，机械生成；派生缓存，不进 Git
screen_guidance

方向、重点、事实边界和 exact 义务。

narration.beats

当前 A 可用于扩充上屏内容的具体素材。

presentation

rough 投影出的表达结构、关系和媒体安排。

exact — 逐字义务 标记为 exact 的内容必须逐字可见，不得改写、拆并或省略。
reference — 可再创作 普通 reference S/G 不需要逐项复现；允许改写、拆分、合并、扩充和视觉化。
06 · Human Gates

最关键的人工门禁

五道真正不可自动越过的节点。其余检查可以自动化或由流程兜底，这五道只能由用户亲手放行。

GATE 01

批准连续口播

没有用户明确批准，就没有批准口播文件，也不能生成 A-page。

approved-spoken-text.txt
GATE 02

批准 visual rough

粗设必须由用户审阅，才能从 draft 变为 approved。

episode-XX-visual-rough.md
GATE 03

Checkpoint Plan

同时确认 script、Outline、主题、素材和开发模式，五项对齐才开工。

已批准的生产计划
GATE 04

第 1 章验收

必须是完整版本，不允许先交骨架；用户验收前不能继续批量制作。

Chapter.tsx · narrations.ts
GATE 05

Checkpoint Audio

网页制作完成后必须询问是否合成音频；合成前还要先确认分段文本。

audio-segments.json
