## 1. 背景与链路变更

### 1.1 为什么重制

模块 1 润色稿经三份 subagent 审读 + 机械统计诊断，问题分五类：审核口吻换皮、免责声明复读、句式模板化、节奏等长化、润色覆盖不均。关键验证（2026-08-06 对照实验）：干净 subagent 严格按现有 4 份指导文档独立润色 ep05，只做 4 处"删教材"式改动（10 段中 6 段逐字保留，产物仍含 1 处"教材"残留），不触碰任何句式/节奏/免责问题——**问题出在 skill 标准，不在执行**。

结论：V1 只定义了"删禁用词 + 机械校验"（合规清洗），没有定义"自然讲解"的质量标准。V2 把质量标准正式化，并把润色搬进任务包。

## 3. 润色对象与边界（A3/A4 细化）

### 3.1 可改写范围

- **唯一改写对象**：§6 `[Nxxx]` 段正文（含段内标点与分行）。
- **只读参照**：§3.3 受保护内容（必须保留的数字/术语/关系）、§4 叙事链与段落职责、§6.1 时长预算（存在时，**历史估算，润色不更新**，见 §8 项 4）、§7 B 表（B 边界、锚点、时间、揭示顺序、转场）、§7.1 映射声明、§8 媒体表（锚点词与媒体联动）、§10 生产约束。
- **禁止改写**：除 N 段正文外的任何章节内容、B 表结构、映射关系、编号体系。

### 3.2 产出物格式

- §6 保持纯 `[Nxxx]` 块结构，**不在 §6 内插入 `[B01] N001–N002` 分节标注**。原因：`task_package.py` 的 `_parse_narration` 以 N 标记为界切分正文，B 标注行会粘连进相邻 N 段内容，污染 PPT 轮消费的文本。
- B 边界的权威来源 = §7 B 表（讲稿 ID 列 + 尾行"恰好映射一次"）。PPT 轮按 B 表取 B 边界，无需改解析器。
- 若后续确需在产物中显式标注 B 边界，应在 §6 之后新增独立映射块（如 `§6.2 B/N 边界清单`），不改变 §6 内 N 块结构——本方案默认不采用，列为可选项（见 §8 项 6）。

### 3.3 "教材"归零的结果要求

- **结果态**：§6 全部 N 段正文不得出现"教材"二字（校验器 FAIL 项，作用域 = §6 N 段正文，见 §6）。**作用域外不受限**：B 表锚点、媒体表、§10 等处的"教材"属画面标注/证据归属，不在禁用范围。
- **处理优先级**：润色时以自然讲解为第一优先，不为删"教材"做机械替换。"教材"在自然改写中自然归零；归属语义（受保护数字/结论的来源与叙述性质）必须保留。
- **禁止替代**：不得用"通常""普遍认为""一般认为"等不可验证泛化替代归属。归属语义的保留方式由审读维度 2（内容与合规）把关，机械不可判定。
- **修正清单旧例**：`work/narration-polish-v2-checklist.md` K1 的 ✅ 示例"`2012 年，通常被作为这段历史的起点`"与 2026-08 审阅结论矛盾（"通常"是不可验证泛化、归属丢失，曾判 FAIL）。本方案以 2026-08 审阅结论为准：**"通常"类泛化属于禁止项**（见 §4.2 D5）。

## 4. V2 检查清单（正式化）

### 4.1 前置审核：三维度审读（A7，每次润色前必做）

目的：确定本集修改范围（哪些 N 段/哪些问题要改），输出"修改范围清单"（按 N/B 定位引用）。三个维度由并行 subagent 独立审读，每个 subagent 只负责一个维度：

**维度 1：语言表达与口语自然度**
- AI 腔/模板化句式（"先看 X…再看 Y…""X 是基础/关键/核心"连用）
- 书面残留（长句绕口、被动句过多、抽象名词连排）
- 口语自然度（停顿、语气词、节奏生硬；每段是否同一个"判断句+解释+总结"结构）
- 具体性（全是抽象概括"工业要素/制造资源/业务协同"，缺画面感）
- 段落开头多样性（13 集每段开头是否高度雷同）

**维度 2：内容与合规平衡**
- 审核口吻换皮（"教材没有给出…"→"需要说明的是…"这类免责声明化）
- 限定语失衡（a. 过度堆砌：同一限定相邻多段重复；b. 缺失：任务包受保护数字/限定被漏）
- 事实漂移（对照润色前基线——git diff 数字/年份 token 对照 + 归属语义抽查，见 §7.2 步骤 4.5）
- 段落职责（对照任务包：负责提问的段是否被磨成总结段）
- 删除过度（有价值的具象信息是否被删成抽象概括）

**维度 3：教学叙事与节奏**
- 节奏起伏（是否平铺直叙——每段等长、每段一个功能，无紧张-松弛交替）
- 开头吸引力（N001 是否千篇一律"设想/在一座…里"；快速建悬念还是干讲术语）
- 段落功能多样性（对照任务包 beat 职责：提问段/案例段/转折段/交接段是否被磨平）
- 提问与互动（"为什么…？因为…"机械自答连发；伪提问）
- 结尾（"回到开头+下一集预告"固定句式收尾）
- 叙事链完整性（案例是否被讲成概念罗列）

产出：每维度一份发现清单（引用 N/B 位置 + 原文摘录 + 问题类型），合并为修改范围清单。范围清单是润色的直接输入，也是后置复核的对照基准。

### 4.2 删除类（改写时必须处理）

- **D1 审核口吻换皮**："需要说明的是/需要强调/必须强调/值得注意的是/当然，这…（兜底）/本集不替它讨论…/本案例没有提供…/这里没有展开…/并不在这条路径中展开/之所以…是因为…的台账式自问自答"。判定标准：删掉后听众是否仍然理解该知识？是 → 删；否 → 信息自然融入讲解，不用免责句式。
- **D1a "本集/本单元"标签**（P2-3 明确归属）：**不加入禁用词表**。议程声明式标签（"本集要处理…""本集先把方向和边界说清楚"）删除或口语化（"这一集"）；内容边界式表达（"本集只讲共同表达的必要性""本集先停在组织决策层"）由 D1 判定标准处理（删掉后听众是否仍理解）并**在自查清单记录判定**。归 D1 人工判定，机械不查。
- **D2 免责声明复读**：同一限定全篇只出现一次，且必须出现在数字首次出现的那一段；相邻段重复 → 保留首次，删除或大幅弱化后续。
- **D3 证据台账术语**："没有提供统计周期、样本规模、基线和计算方法"类台账语言不得直接念给听众；需表达"数字是案例值"时用一句话自然带过（"这个数字来自该案例，不能直接当成行业水平"）。
- **D4 元话语/议程声明**："用一句更直白的话来概括""接下来进入行业案例时，可以沿着同一框架观察""先看一个教学情境"（"教学"二字删除，直接进场景）、"这一集先把方向和边界说清楚""这是第一类支撑：…"。
- **D5 不可验证泛化**（本方案新增，修正清单旧例）："通常/普遍认为/一般认为/往往是"等不可验证概括，**不得作为归属替代，也不得作为直陈事实的免罪符**（P1-1：删去旧稿"或直陈事实"分支——受保护内容必须保留"来源/叙述性质"语义，直陈事实只允许用于非受保护内容且不涉及归属的场合）。确需表达历史起点/来源时，用强归属语义（正例见 §4.3 K1）。

### 4.3 保留类（不得因润色丢失）

- **K1 受保护归属**（P1-1 修订）：§3.3 受保护数字/术语必须保留其**归属限定语义**——"来源"（谁说的/哪个导则/哪个案例）与"叙述性质"（这是历史叙述的选择，不是本集新断言）二者至少保留其一；结果态不含"教材"二字。禁止变成无归属的已核验断言，禁止"通常"类泛化替代。
  正例（执行最易走样处）：
  - ✅ 受保护年份+时点（ep43 类）：原文"教材转述的导则要求，二级节点责任主体必须是独立法人单位" → "**2021 年发布的建设导则**要求，二级节点责任主体必须是独立法人单位"（保留年份与导则时点语义）
  - ✅ 历史起点叙述性质（ep01 类）：原文"教材以此为历史起点" → "**这段历史，我们从 2012 年讲起**"（"我们…讲起"表明叙述选择，无泛化词）
  - ✅ 案例结果限定（ep09–13 类）：原文"教材所述案例显示…" → "**这一案例的结果是…**"（明确案例范围，不滑向全行业断言）
  反例：❌"2012 年是工业互联网的诞生年"（丢失叙述性质）；❌"2012 年，通常被作为这段历史的起点"（不可验证泛化）。
- **K2 必要限定（每集保留一次）**："这是该案例的结果，并不是所有外协企业的现状""安全闭环只限于本案例表述"等改变知识含义的限定——保留，只保留一次。
- **K3 结构与职责**：N 段数量/编号/顺序/边界、数字/年份/单位、专业术语、与 PPT 同步的关键词（清单项、关系方向、案例对象）全部保留；段职责（提问段/案例段/交接段）不变；B 内锚点/揭示顺序/时间权重保持（见 §5）。

### 4.4 破模板类（语言层）

- **T1** "不是…而是…"对仗：每集 ≤ 2 次，超过的改写为直陈句。
- **T2** 判断句直开/枚举段："X 是基础/关键/核心"连续判断段 → 至少两段换开头（提问、例子、反例、场景）；"第一类支撑…第二类…第三类…" → 保留信息，打散结构。
- **T3** 机械连接词："所以/因此"每集合计 ≤ 3 次；"这样一来/也就是说/换句话说"每集合计 ≤ 2 次；"回到开头 X"收尾每集最多 1 次，且回扣携带新信息（升级，不复述）。
- **T4** 术语连排：一句内 ≥ 3 个抽象术语连排 → 拆句，用具体名词或动作替代抽象名词。
- **T5** 结尾模板："下一集，我们将…"每集最多 1 次且必须换说法；13 集（同模块）不允许连续两集同一收尾句式。

### 4.5 节奏类（结构层）

- **R1** 段落长度梯度：悬念/场景段 80–120 字；机制/讲解段 120–160 字；总结/收束段 80–120 字；连续两段长度差 < 15 字 → 需要调整；每集最长段与最短段之比 ≥ 1.5。**优先级声明（P0-1）：R1 段长梯度让位于 B 时间权重**——B 时间权重是 PPT 轮排布依据，R1 仅为统计参考，两者冲突时以 B 时间权重为准。**例外记录机制（P3-4）**：真实数据存在超限段（如 ep05 N006 实测 204 字符、N008 187 字符，超过机制段上限 160），允许例外但必须在自查清单记录段号与理由。
- **R2** 开头多样性：禁止连续两集用同一种开头模式；每集开头 30 秒内必须有场景、画面或直接提问，不得从术语定义开场。
- **R3** 提问节奏：问题与答案至少隔 1 句（先给材料，再揭答案）；禁止"为什么…？因为…"机械自答连发。
- **R4** 锚点回收：开头场景一集内最多回扣 2 次，回扣携带新信息（升级），不复述。

### 4.6 约束力分级（A6）

| 级别 | 规则 | 执行方式 |
|---|---|---|
| FAIL（机械判定） | D3 台账词残留；K3 结构与边界（N 序列/段外字节/编号）；B/N 映射完整性；B 文本锚点关键词存在性（每集锚点词表可查子集，见 §5.2）；禁用词（教材/本任务包/脚本设计/后续制作/PPT 制作/PPT制作/审核通过，作用域 = §6 N 段正文）；受保护数字/术语存在性（**弱检查**：全篇存在） | 校验器 v2 直接判定，不满足即 FAIL |
| 统计输出（人工判定） | T1–T5、R1–R4 全部量化指标（R1 例外记录机制见 §4.5）；B 时间权重**相对漂移**偏差（§5.3）；免责声明模式计数；段落长度列表；**非受保护数字/年份变化**（对照 git diff，变化须在自查清单记录原因） | 校验器 v2 输出统计，润色者写入自查清单，审阅时人工判定（允许合理例外，如 ep07/12 T1=3 先例） |
| 审读判断（不可机械判定） | D1/D1a/D2/D4/D5、K1 归属语义、K2 限定一次、T2/T4 语义层、R2–R4 语义层、段落职责、叙事链、受保护映射**强检查**（§3.3 标"必须与…同现"者，归属同段，试点定 FAIL 或人工） | 前置审读（§4.1）发现 → 改写处理 → 自查记录 → 步骤 4.5 复核 → 审阅复核 |

## 5. B/N 粒度约束（润色单元 = B）

### 5.1 基本原则

- 润色单元从"N 粒度"升级为"B 粒度"：每处改写必须保持所在 B 的**锚点、语义揭示顺序、时间权重**；跨 B 的改写（把 B2 的信息挪进 B3）一律禁止。
- N 结构不变（A4）：N 编号/数量/顺序/边界、B 表讲稿 ID 列、尾行映射、§7.1、§6.1 段数全部不动。B 粒度约束因此表现为"**在 B 边界内逐 N 改写**"，不改变任何映射。

### 5.2 B 锚点保持（P0-3 机制化）

- 每个 B 的"必须可见的信息"列是其锚点清单，改写后对应 N 段必须仍覆盖全部锚点。
- **锚点三类条目**（每集提取时标注，落盘 `work/narration-polish-v2/<模块>/<集>-anchors.md`）：
  1. **文本锚点**（可机械查）：必须出现在 N 段文字中，如"供应商""二维码可扫描""独立法人单位"——入校验器 FAIL 可查子集；
  2. **视觉锚点**（审读把关）：由 §8 媒体承载，如"教学情境""写实收货核验场景"——不入文本可查子集；**含禁用词的锚点条目（如 ep05 B05"教材图 1-4 全貌"）归视觉锚点**，由 §8 媒体承载，不触发 §6 禁用词 FAIL（P1-3 一致）；
  3. **否定约束**（转人工检查）：如 ep43"不出现技术指标""不出现企业名"——不机械查，由审读维度 2 把关。
- **受保护数字映射（P0-3）**：弱检查 = §3.3 受保护数字/术语在全篇存在（FAIL）；强检查 = §3.3 标"必须与…同现"的归属关系（如"2021 年只用于说明教材引用的导则时点"）——归属词必须与数字同段，试点（ep05/23/43）定 FAIL 或人工，校准后固化。

### 5.3 B 时间权重匹配（P0-1 相对漂移口径）

- **校验口径 = 相对保持，不罚基线**：比较润色前后同一 B 的**字符占比**变化，仅惩罚漂移：
  - B 字符占比 = Σ(该 B 内 N 段去空白字符数) / Σ(全部 N 段去空白字符数)
  - 漂移 = (润色后占比 − 润色前占比) / 润色前占比
- **基线偏差是已知常数，不参与判定**：ep05 原始基线实测 B01 −39%、B05 −46%、B07 −27%（相对"时间中值×230/60"绝对目标；B07=N010 实测 146 字符，早期报告的 +68% 系把 §6.1 内容误并入 N010 所致，已复算更正），试点先记录 3 集基线偏差分布作为已知常数（校准前先测）。
- 漂移阈值：初始 ±20%（统计输出，不 FAIL），试点 3 集数据收集后校准（见 §8 项 8）。
- **优先级**：R1 段长梯度让位于 B 时间权重（§4.5）；ep43 无 §6.1，以润色前字符占比为基准（B 表时间仅用于初始目标估计）。
- **校准落盘**：基线偏差与漂移判定落盘 `work/narration-polish-v2/<模块>/baseline-drift-<集>.json`（格式见 §8 项 8）。
- §6.1 的"字符当量"口径（如 ep05 的 1341.5）与实测字符数（汉字 1339/去空白 1474，N 段口径不含 §6.1）不一致——**不作为校验依据**（§8 项 4 历史估算定位）。

### 5.4 语义揭示顺序

- B 表"语义揭示顺序"列描述段内信息出现次序（"先…再…随后…最后…"）。机械不可可靠判定，由审读维度 3 把关；校验器只输出该 B 的 N 段字符占比（供对照顺序权重失衡）。

## 6. 校验器 v2 规格（A5）

- **位置**：`work/validate_narration_v2.py`（与 `work/validate_package_structure.py` 并列，SPEC-DRIVEN 同族；实施后如需迁移另行决策）。
- **输入**：单集任务包路径（`--episode XX` 或 `--package <path>`）+ 该集锚点词表（`<集>-anchors.md`，步骤 1.5 产出）。**不再需要快照**：就地润色后"输入冻结"语义失效，改为包内自洽校验 + 润色前后 diff 对照。
- **解析**：复用 `work/classroom-html-ppt-skill-revision/scripts/task_package.py` 的解析面（N 块、B 表、§3.3 可先按章节文本正则提取）。
- **检查项**：
  - FAIL 类：N 序列完整（N001 起连续递增、无重复）；§6 段外字节（N 块之间无非空杂散文本；**豁免清单**：§6 标题行、声明行如 ep43"以下 N001–N014 为本集唯一可录制口播文字来源"；检查范围限定"N 块之间"与豁免行之外）；禁用词（作用域 = §6 N 段正文，含"PPT制作"无空格变体）；受保护数字/术语存在性（§3.3 弱检查：全篇存在）+ 强检查（"必须与…同现"者，试点定 FAIL/人工）；B/N 映射完整性（尾行逐条成立、B 表引用的 N 均存在）；B 文本锚点关键词存在性（§5.2 可查子集）。
  - 统计类：段落长度列表与 R1 指标（梯度、最长/最短比）；T1/T3/T5 句式计数；免责声明模式计数；"通常/普遍认为/一般认为"计数（D5 提示）；B 时间权重**相对漂移**偏差（§5.3）；非受保护数字/年份变化（需传入润色前基线，见步骤 4.5）。
- **快照退役**：`work/narration-polish-v1/baseline-sha256.json` 不再被校验流程消费；回退通道 = git 历史（§1.3）。
- **旧脚本处置**：`validate_narration.py` 保留文件、标注退役（实施阶段在脚本头部加注释），不删除。

## 9. 验证方式

## 10. 会话组织与上下文策略（2026-08-07 用户决策：每模块一会话）

执行粒度：**每个模块一个会话**（模块 1–5 共 5 个润色会话 + 前置实施会话）。上下文预算（按 0.75 token/字）：单集任务包 ~10K tokens，整模块 13 集任务包全文 ~128K tokens——**禁止整模块读任务包**。

### 10.1 会话纪律（防 R1 溢出）

- 每集只读当前集任务包的关键章节（§3.3/§4/§6/§6.1/§7），不整模块读。
- 每集完成后：修改范围清单、锚点词表、自查清单、登记表行**全部落盘**；该集工作集从上下文归档（只保留登记表行与提交 hash）。
- 会话内活跃上下文 = 当前集工作集（~20K）+ 模块登记表 + 固定规则（V2 检查清单摘要）≈ 25K tokens 以内。
- 主会话不保留已提交集的全文；恢复续跑时从登记表定位断点。

### 10.2 前置审读（每集）

3 个并行 subagent（delegate_task 批处理），各自独立上下文，各读本集任务包全文（~10K tokens/个）+ 模块登记表（供跨集属性参考），输出修改范围清单。主会话只接收合并后的清单（~3–6K tokens）。

### 10.3 后置审读（模块级，统计先行双轨，防 R3 超窗）

- 主会话先用提取脚本从登记表 + 各集自查清单产出**机械统计包**：每集开头句/结尾句原文列表、T1/T3 计数、段长列表、免责模式计数、"教材"残留（§6 N 块作用域）grep 结果、**每集 git diff 数字/年份对照表（P0-2）**、登记表全量。
- 3 个审读 subagent 读**统计包 + 登记表 + 抽查片段**（不强制 13 集全文，~100K tokens 贴线风险）。抽样规则（P0-3 审查项）：每个维度至少抽查 3 集全文片段 + 全部集的统计行；发现异常的集升级为全文审读。
- 跨集属性（T5 结尾去重、R2 开头多样性）用登记表逐集对照判定，比读全文更精确。

### 10.4 中断恢复
