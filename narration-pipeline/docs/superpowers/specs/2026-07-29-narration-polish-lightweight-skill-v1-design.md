# 51 集口播润色轻量 Skill V1 设计

## 状态与目的

本设计自 2026 年 7 月 29 日起取代 `2026-07-29-narration-polish-execution-skill-design.md`。

目标只有一个：让 Agent 直接在独立目录中修改口播稿，同时不改任务包和原始口播，并用少量机械校验降低漏段、错号、数字漂移和目录误写风险。

## 权威关系

1. `episodes/<module>/episode-XX-...-task-package.md` 是 PPT、分镜、视觉锚点和事实边界的第一来源，只读。
2. `outputs/narration-scripts/<module>/episode-XX-...-narration.md` 是润色前原始口播，只读。
3. `outputs/narration-scripts-polished/<module>/episode-XX-...-narration.md` 是唯一允许修改的口播交付目录。
4. `docs/superpowers/specs/2026-07-28-narration-script-full-polish-design.md` 继续定义内容如何润色。

发现任务包、原始口播和 N 段映射互相冲突时，停止当前集并报告，不在本流程中修复输入。

## 最小组成

Skill 只保留以下能力：

- `SKILL.md`：读取顺序、允许写入范围、逐集工作流和人工自检表。
- `scripts/narration_core.py`：发现 51 集、解析 N 段、提取数字和计算 SHA-256。
- `scripts/initialize_polished.py`：首次复制 51 份独立副本，并记录一个简单输入哈希快照。
- `scripts/validate_narration.py`：校验单集或全批次的机械约束。
- 对应的标准库 `unittest` 测试。

唯一运行时证据是：

```text
work/narration-polish-v1/baseline-sha256.json
```

它只记录任务包和原始口播的相对路径与 SHA-256，用于证明润色期间输入没有变化。它不是状态机，不记录 writer、reviewer、事务、重试次数或发布状态。

## 初始化流程

1. 检查任务包与原始口播各 51 份，模块分布为 `13, 7, 12, 10, 9`，集号完整为 01–51。
2. 当润色目录不存在时，逐文件原样复制到相同模块结构。
3. 初始化中断后，只允许 `--resume` 补齐缺失文件；已有文件必须仍与原始口播逐字节一致，否则停止，不覆盖。
4. 复制完成后写入输入哈希快照。
5. 将 51 份初始副本和哈希快照提交到 Git，后续恢复依赖 Git。

## 单集润色流程

1. 选定一集，不并行处理其他集。
2. 完整读取该集任务包、原始口播、润色副本和内容规范。
3. 只修改润色副本的 `[N001]` 至最后一个 `[Nxxx]` 正文；N 段外内容保持不变。
4. 保留事实、数字、单位、限定语、结论强度、N 段职责和视觉锚点。
5. 删除面向编写者的审核口吻，但不以新的审核口吻替代。
6. 运行单集机械校验。
7. 按内容规范人工通读一次；有事实或映射疑问就停止并报告。
8. 每集单独提交润色文件。中断后通过 `git diff` 继续，不建立恢复状态机。

## 机械校验

单集校验只负责可以确定性判断的内容：

- 原稿与润色稿 N 编号序列完全一致且连续；
- N 段外前缀和尾部说明逐字符一致；
- 每个 N 段非空；
- 每个 N 段的数字、百分比和数字范围与原稿一致；
- 润色稿不含内容规范明确禁止的幕后措辞；
- 输入哈希仍与初始化快照一致。

全批次校验只增加：

- 润色目录恰好有 51 份目标文件；
- 相对路径与原始口播一一对应；
- 五模块数量和 01–51 集号完整；
- 所有单集机械校验通过。

事实等价、术语语义、限定语强度和视觉锚点是否自然保留，仍由 Agent 依据任务包和内容规范判断，不伪装成机器可证明结论。

## 明确非目标

V1 不实现：

- `run-state.json` 或 episode manifest；
- 状态机、重试计数或 `SEMANTIC_PASS`；
- writer/reviewer 身份系统；
- 文件锁、并发发布、事务日志或崩溃恢复协议；
- 原子目录发布；
- 自动修改任务包或原始口播；
- 自动提交或自动回滚用户内容。

## 验收标准

1. Skill 可被发现并明确触发于本课程口播润色任务。
2. 初始化可生成 51 份独立副本，且不会覆盖已有不同内容。
3. 单集校验可发现 N 段变化、N 段外变化、数字变化和输入变化。
4. 全批次校验可发现缺失、多余或错路径文件。
5. Episode 01 试点能够按“读取任务包 → 修改独立副本 → 校验 → Git 提交”完成。
6. 整个实现不包含复杂执行设计中已废弃的状态、锁和恢复组件。
