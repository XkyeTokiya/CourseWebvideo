# Polish Stage1 Narration（口播稿润色）

仅限人类明确调用。支持两种模式；先按用户给出的文件判断模式，不要把历史 work 产物猜作当前输入。

## 模式与输入

### 连续稿模式

- 口播稿：`..\.tmp\narration-pipeline\<任务目录>\episode-XX/stage1-continuous-draft.md`
- 事实约束：同目录 `narration-brief.json`

适用于 A-page 尚未发布，或用户明确要求润色连续稿的情况。

### 成品 A-page 模式

- 主输入：`..\player\episodes\episode-XX\inputs/episode-XX-a-page.json`，且 `schema_version` 必须为 `courseplay-a-page/v4`
- 同步目标：同目录 `approved-spoken-text.txt`
- 正式校验报告：同目录 `episode-XX-a-page-validation.json`

适用于用户明确要求润色成品 JSON、A-page、某个 `a_id` 或 `pages[*].nx` 的情况。此模式必须完整读取 [references/finished-a-page-mode.md](references/finished-a-page-mode.md)，并把 A-page 的页面语义、证据和受保护关系视为不可越过的事实契约。

若用户同时明确给出对应 `narration-brief.json`，一并读取；不要仅凭相同 `episode_id` 从 `.tmp/narration-pipeline/` 中猜选旧 brief。

## 与重写 Skill 的职责边界

- 本 Skill 必须以一份既有连续稿或既有 A-page Nx 为编辑对象，输出仍是同一稿件的局部修订版。
- 不执行 `rewrite-course-narration` 的 Brief → 新连续稿流程，不重新设计叙事问题、开场、正文结构或结尾，也不以“整体更自然”为由成段替换原稿。
- 如果问题必须通过重排论证、替换案例、补充事实、改变内容义务或重新切分页面才能解决，将其标为“需要重写/重新编译”，停止该项润色并建议转交相应 Skill；不要在当前 Skill 内继续扩展范围。

## 共同流程

1. **完整通读并预检**：读取当前模式的全部输入，建立事实、术语、范围和文件一致性基线；把 brief 内容区分为“学习者必须理解的内容”“Agent 静默遵守的写作护栏”“与口播红线冲突的上游要求”。
2. **红线清理通道**：逐段找出学习者口播硬红线，明确删掉哪一段外壳、保留哪一段领域内核。
3. **常规润色通道**：在脑中应用红线删除后的版本上，从头到尾重新审读一遍语法、搭配、指代、专业关系、口播节奏、段落衔接和重复表达。红线清理不能代替这一步。
4. **先给两份短清单，等待确认**：先列“红线清理”，再列“常规润色”；均使用“序号 / 位置 / 原句 / 问题 / 建议改法 / 级别”。红线级别为“必须删除”，常规润色级别为“建议修改”或“可选优化”。重复问题可以合并，但必须列全位置。用户确认或指定序号前，不修改任何文件。
5. **单独报告上游问题**：brief 遗漏、brief 与红线冲突或需要新增事实的事项放在清单之后，不编号、不拟写口播替换句，也不混入可确认的润色项。
6. **按确认范围应用**：采用能解决问题的最小局部修改；删去内部话语，只在原句确有受支持的领域内容时保留该内容。不得把制作、审计、图示解释或证据台账说明改写得更顺口后继续放在口播里；不增减事实信息，不顺带改未确认内容。
7. **回读与校验**：逐条对照确认清单，并对修改后全文及“建议改法”列再次执行红线扫描，确保内部话语没有被换一种说法保留下来。连续稿模式回读修改处；成品模式还必须完成 Nx 同步、机械时长重算和正式 A-page 校验。

用户只要求检查时，完成两份诊断清单和必要的上游问题报告后停止，不写文件。

## 常规润色：必须独立完成

红线清理只是输入卫生，不等于口播润色。完成红线通道后，必须把删去红线后的稿件当成一篇完整口播重新通读，至少检查：

- **句法与搭配**：句子主干是否完整，数量词、介词、动词和宾语是否搭配自然，是否有半句、病句或书面语倒装。
- **指代与主语**：`这、这个、它、它们、前者、后者`能否在听觉中立即找到对象；跨句主语是否无故漂移。
- **逻辑与专业关系**：动作先后、因果、条件、主体职责和术语关系是否准确；不能只把专业句改得更正式，却保留原来的关系混淆。
- **口播节奏**：按实际朗读判断停顿和信息密度；长句不是按字数判错，短句也可能因连续跳跃而难听懂。
- **段落衔接**：上一句提出的问题是否由下一句回答，转折是否真实，段首是否突然换对象。
- **重复与收束**：相邻句或结尾是否重复同一结论；删除红线后是否留下断裂、空转或重复过渡。
- **自然教师语气**：保留准确、好懂的口语、比喻、反问、对照和回扣。不能仅以“像金句”“略口语化”“否定式排比”为由修改，更不能把`同一盒药`这类贴合上下文的说法机械换成抽象术语。

常规润色清单必须给出可直接评估的完整替换句，不能只写“直接陈述方案”“必要时改得更自然”“保留领域内核”等操作说明。若一句原文同时含红线和语言问题，拆成两个项目：红线项只说明删掉哪段外壳；常规润色项再比较去壳后的句子怎样改。`必须删除`只能作用于明确要删除的文字，不能覆盖整段中仍需保留和润色的内容。

以下是本轮样例体现的常规问题类型：

- `中间经过哪段仓储和物流？` → 检查数量与搭配，可改为`中间经过哪些仓储和物流环节？`
- `回答了这个，它不同阶段的记录才可能关联到一起。` → 指代和主语不清，可改为`明确这盒药的身份后，不同阶段的记录才可能关联起来。`
- `现在停在哪类环节` → 搭配生硬，可改为`当前处在哪个环节`。
- `标识解析给……发一个全球唯一的编码，再通过解析……` → 不能只把“发”换成“提供”；应检查“赋予编码”和“通过标识解析查询”是否被混成同一动作，并在 brief 支持范围内分清关系。

没有发现某一类问题时可以不硬凑修改，但诊断报告必须明确常规润色通道已经完成，不能只交一份红线删除清单。除非用户明确要求，不输出“人性化评分”或其他无法验证的综合分数；用逐条回读和具体前后对照验收。

## 学习者口播硬红线

本项目明确要求删除下列内容。它们不是“可以保留的必要边界”，也不能通过换词、压缩或口语化继续出现在口播中：

- **情境真实性补丁**：`这是教学情境`、`这是假设情境`、`并非真实事件`、`不对应任何真实企业/药店`，以及作用相同的声明。听众默认理解案例与情境的教学属性，不要反复辩护真实性。
- **课程来源归属**：`课程资料指出/强调/所述/归纳`、`教材中提到`、`课本告诉我们`、`任务包要求`、`案例材料给出/没有给出`，以及“在资料/教材/材料的描述中”等同义改写。
- **制作与画面说明**：`案例实拍`、`图示里/图上`、`视觉参考`、`大屏示例`、`镜头`、`PPT`、`动画`、`素材`、画面上的日期/企业标识/地图/指标，以及“图示没有的内容不展开”。
- **审计免责声明**：`不代表当前行业状态`、`不等同于现行监管结论`、`不能当作行业平均/项目承诺/所有企业结果`、逐项念出`统计周期、样本、基线、计算方法`等缺口，以及作用相同的补丁式限定。
- **未来工作承诺**：`后续查询`、`还需核验`、`审核后替换`、`再补一个案例`等制作或研究待办。

`先说明`、`再看`、`本期总结`等教师组织语本身不在红线内；但它们后面如果连接的是上述红线内容，只能删除红线内容，不能以组织语为理由保留整句。自然口语、否定式排比和对称句也不按形式清除。

Brief 中的 `case_limits`、`historical_scope_limits`、事实限定和审计信息是 **Agent 的写作护栏，不是学习者台词**。正确用法是避免补写越界内容、避免作出无依据结论；错误用法是把这些护栏逐句解释给学习者。

### 修改方向（强制）

1. **先删红线外壳**：删掉真实性声明、课程资料归属、图示/画面说明、审计免责声明和未来待办。
2. **再看是否有领域内核**：剩余部分是否包含 brief 或当前 A-page 已支持的对象、动作、关系或结果？
3. **有内核就直接陈述**：只讲领域内容，不再添加“在课程资料中”“这是个假设”“图示表示”“不代表某种结论”等前后补丁。
4. **没有内核就整句删除**：纯真实性声明、纯画面说明、纯审计缺口或纯待办不生成替代句。
5. **内核在邻句已经讲过，也整句删除**：不要为了维持原字数重复讲一遍，更不要用新的边界句填补时长。
6. **无法在不增加事实的前提下直接陈述，就在口播外上报**：不要用免责声明把风险转嫁给听众。

如果原稿含“课程资料所述方案效益为交期缩短百分之二十”，只有当 brief 或 A-page **允许该结果脱离红线归属独立陈述**时，才可改成`方案实施后，交期缩短百分之二十。`如果 brief 明确要求百分之二十必须与“课程资料所述”等红线限定同现，则该数字不能进入口播；删除并报告“brief 与学习者口播红线冲突”。不得擅自去掉限定后把数字说成无条件事实。

修改完成后做两次扫描：

- **原稿扫描**：每个硬红线命中都必须进入删除或直述处理，不得在清单结尾声明“这些内容会保留”。
- **建议改法扫描**：建议句中不得再出现课程资料归属、情境真实性补丁、图示/画面解释或审计免责声明；命中即表示修改方向失败，必须重做。

最后做“独立口播测试”：脱离任务包、教材、课程资料、图示、PPT、审核记录和制作上下文，这句话是否仍在直接解释课程对象？如果不是，删除它。

不要把红线清理扩大成重写：不另造开场或结尾，不改变论证顺序，不跨段重排，不替换案例，不补充 brief 外知识，也不机械修改本来已经自然、准确、可朗读的领域句子。

## Brief 的使用方式

Brief 是事实与范围契约，不是待复制的口播措辞库。读取时分三类：

1. **学习者内容义务**：需要保留其语义，但用现有稿件的自然表达承载，不照抄 brief 的报告腔、来源归属或制作说明。
2. **Agent 静默护栏**：`case_limits`、`scope`、不得补充的系统/协议、不得夸大的结论等，只约束修改行为，不转述给学习者。
3. **与硬红线冲突的要求**：若 brief 要求明确念出“非真实事件”“课程资料所述”“不代表行业状态”或要求某个事实必须与这些措辞同现，不在润色中强行满足。删除对应口播，并在清单外报告上游 brief 冲突。

Brief 中有而现稿没有的事实或核心判断，不属于“发现病句后顺手补齐”。只报告内容缺口，不提供新增口播句；否则当前 Skill 就会越界成重写。

## 诊断重点

- 语法：被动生硬（“被作为”“被描述为”）、动宾搭配不当、歧义、重复啰嗦、冗余。
- 节奏以实际朗读和理解负担判断，不以字符数直接判错。只有一句同时承载多层关系、缺少自然停顿或容易让听者丢失主干时才建议拆分。
- 并列项能够顺畅朗读时可以保留；出现持续堆叠或层级混杂时，再用停顿、分号或局部拆句处理。
- 主动句优先，但保留原有口播语气和自然比喻，不做书面化重写。
- 政策文件首次出现使用已核验的官方全称；涉及可能变化的名称或日期时，只以用户给出的权威材料为准，或经官方来源核实后再建议。
- 抽象名词连续充当主语并确实妨碍理解时，才检查能否在不增加事实的前提下还原为具体对象和动作；定义、总结和必要概括可以保持抽象表达。

## 事实与语义边界

- 不得与 brief 的 `facts_and_qualifiers`、`scope` 冲突；`protected_terms` 不得替换。
- 成品模式不得改变对应页的 `teaching_purpose`、`single_message`、`must_visible`、`protected_relations`、进入/退出条件，也不得移动页面边界。
- 拆句或调序不能改变主语、事实归属、因果、限定语、强调重点或制造新结论。
- 如果建议只有在改变事实、教学意图、页面归属或受保护关系后才成立，将其标为“超出 Nx-only 润色”，不应用；告知用户需要重新编译 A-page 或显式批准成套语义修改。
- 删除硬红线时只保留领域事实内核；真实性补丁、课程来源、图示解释和审计免责声明本身不属于必须保留的事实限定。无法安全提取领域内核时，整句不进入口播，并在口播外上报。

## 停止规则

- brief、A-page 页面语义与口播事实互相冲突时，停止相关修改并上报，不自行决定谁覆盖谁。仅有 brief 措辞与学习者硬红线冲突时，按“Brief 的使用方式”删除相关口播、报告上游冲突，并继续处理其他安全的润色项。
- 真正要求执行未来查询、核验或补案例的内部待办，只作为上游内容缺口报告。材料缺少统计周期、样本、基线等审计信息时，通过不作越界推断来处理，不把缺失项清单念给学习者。
- brief 中发现现稿遗漏某项内容义务时，将其单独报告为“上游内容缺口”；不得在润色清单里直接拟句补回，也不得在结尾顺手增加新的核心判断。补内容属于重写或重新编译。
- 成品模式预检发现 `concat(pages[*].nx)` 与现有 `approved-spoken-text.txt` 不一致时，先报告漂移，不在润色过程中静默覆盖。
- 找不到成品模式所需的正式 compile trace 或冻结任务包时，可以完成已批准的 Nx 与连续稿同步，但不得声称成品发布完成；必须报告正式 validation 尚未刷新及缺失输入。

## 失败样例回归

- `先说明，这只是个教学情境，不是哪家药店的真实事件。` → 删除真实性补丁；若`先说明`后没有其他领域内容，整句删除。
- `课程资料所述的三类痛点……` → 删除`课程资料所述`，直接讲三类具体问题。不得改成`在这个案例的描述中`或`这三类痛点只用于概括案例`。
- `交期缩短百分之二十只属于课程资料所述方案效益，不能当作行业平均、项目承诺或所有企业的预期结果。` → 禁止作为建议改法。本轮 brief 又要求百分之二十必须与该红线归属同现，因此应删除这个数字，并在口播外报告 brief 冲突；不能直接改成无条件的“方案实施后缩短百分之二十”。
- `这些关系表达的是业务语义，不代表接口顺序；图示没有的系统不在这里展开。` → 默认整句删除，不制造替代免责声明。
- `案例中的供应链数据大屏只是视觉参考；其中的画面内容不代表当前行业状态。` → 删除画面与行业状态说明。只有“多环节数据形成监测视图”是受支持且必要的内容时，才直接讲该领域关系。
- `资料没有给出统计周期、样本、基线和计算方法。` → 从口播删除；不压缩成另一句审计边界。
- `本期总结。` → 可以保留；它是明确的教师组织语，不包含真实性、来源、制作或审计红线。

## 示例（历史锚点句）

- 原：在这段历史叙述中，2012年被作为通用电气，也就是GE，提出工业互联网概念的历史起点。这个说法不是在宣称全球唯一的首创，而是在确定一个重要的历史节点。
- 改：这段历史叙述以2012年为时间坐标：通用电气，也就是GE，正是在这一年提出了“工业互联网”的概念。把这一年作为起点，不是要宣称全球唯一的首创，而是要为这段历史确定一个重要的节点。
