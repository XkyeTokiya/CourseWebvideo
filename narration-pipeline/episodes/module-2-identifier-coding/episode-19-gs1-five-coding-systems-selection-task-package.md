## 2. Episode Positioning

- 主解释问题：同一件工业物品可能同时面对供应链、数字资产、网络资源、物联网和贸易流通等不同任务，VAA、Handle、OID、Ecode、GS1 怎样按业务约束选用，为什么不能用一套编码替代全部体系？
- 一句话结论：选型先看对象和业务边界，再看体系提供的管理入口、编码结构和典型场景；GS1 更贴近贸易流通中的商品与资产识别，VAA、Handle、OID、Ecode 分别有教材所述的供应链/生命周期、数字资产、网络资源、物联网应用语境，跨体系工业应用还需要兼容与映射，而不是把某一体系冒充万能编码。
- 纳入范围：教材 2.1.2 中 GS1 的定义、组织与中国大陆授权管理机构表述；GTIN、SSCC、GIAI 的典型应用语境；GTIN 的厂商识别代码、商品项目代码、校验码三段结构及教材示例；表 2-1 对 VAA、Handle、OID、Ecode、GS1 的示例、特点与场景；按对象、业务边界、跨企业互联、内部细分和校验需求组织的比较决策；教材关于多体系兼容性不足、需要工业制造兼容方案的结论。
- 排除范围：第 15–18 集已经完整解释的各体系治理历史、树状路径、V/NSI/MD 等内部字段；GS1 当前规则、授权状态、编码长度和产品版本；具体注册入口、企业申请、解析接口、条码打印、载体选型；把教材示例数字当作真实注册凭据；行业普遍收益、政策状态、当前市场占有率；第 20 集的字段设计与规则落地。
- 相邻分集边界：第 15 集负责 VAA 三层结构，第 16 集负责 Handle 前缀/后缀与分布式解析，第 17 集负责 OID 树状命名，第 18 集负责 Ecode 的 V/NSI/MD；本集只回顾它们在表 2-1 中的典型语境，不重讲结构。第 20 集负责具体编码规则设计，本集只输出选型约束。

## 4. Content Type and Narrative Strategy

- 主类型：Comparison and selection（比较与选型）。观众需要在约束下选择编码语境，而不是再记一遍五个定义。
- 次类型：System mechanism（系统机制）。只用于解释“对象—场景—结构—跨体系映射”的关系，不讲解析系统内部实现。
- 本集叙事链：一个对象遇到多套编号 → 先把选型维度从名称转为业务问题 → 看 GS1 的贸易流通入口与 GTIN 结构 → 将五体系放入场景矩阵 → 用三个匿名业务情境走决策路径 → 处理跨体系兼容与映射 → 收束“选择边界而非万能编码”的结论。
- 问题闭合方式：先承认多套体系并存是事实，再用教材表 2-1 把五类编码放在同一张语境矩阵中；GS1 的 GTIN 只作为结构示例，不把它提升为其他工业对象的默认方案；最后回到教材关于兼容方案的判断，给出可迁移但不超出证据的选型检查顺序。

## 6. Continuous Narration Master Script

以下 N001–N014 是本集唯一可录制口播文字来源。任何后续页面、分镜或备注只能引用这些 ID，不得另写第二份讲稿。

[N001]
同一件零部件，可能先进入贸易流通，再进入仓储和生产，还要在企业内部系统或工业网络中被查询。每个环节都可能已有自己的编号。今天我们不再逐个背诵缩写，而是回答一个选型问题：面对 VAA、Handle、OID、Ecode 和 GS1，应该先看什么，再做决定？

[N002]
先把“选哪一种编码”改写成四个业务问题：我们要识别的对象是什么，主要在哪个环节使用，是否需要跨企业或跨地域关联，企业是否还要保留自己的对象细分。编码名称只是候选入口，真正的选择取决于这四个约束。教材表 2-1 提供的，正是五种体系的典型语境，而不是一张性能排行榜。

[N003]
GS1 是这张对照表里最贴近贸易流通的一类。教材把 GS1 介绍为由国际物品编码组织开发和维护、广泛应用于全球商贸领域的全球统一标识系统，并称中国物品编码中心负责中国大陆的授权管理。这里按教材记载理解其定位，不把授权关系或当前规则版本延伸成今天的状态判断。

[N004]
GS1 面向不同场景定义了多种编码类型。教材举出的典型代表包括 GTIN、SSCC 和 GIAI：GTIN 用于零售结算，SSCC 用于物流，GIAI 用于资产管理。它们说明一个重要原则：即使同属 GS1，也要先看对象和业务动作，不能把一个类型当成所有场景的通用答案。

[N005]
以教材的 GTIN 示例为例，字符串写作“6901234567892”。图 2-7 将它拆成厂商识别代码、商品项目代码和校验码，示例中分别对应“6901234”“56789”和末尾的“2”。这只是帮助我们读懂结构的教材示例，不是某个真实商品的注册凭据，也不提供额外的长度、分配或校验算法说明。

[N006]
现在把五类体系放回同一张场景矩阵。VAA 在表 2-1 中对应供应链管理和生命周期管理；Handle 对应数字资产管理；OID 对应网络资源管理；Ecode 对应物联网领域，包括物流、仓储和生产制造；GS1 对应产品与服务的贸易流通。这里比较的是教材给出的主要语境，不是说体系只能出现在一个行业。

[N007]
如果对象首先是要进入零售交易的商品，可以先检查 GTIN 的商品项目身份是否满足业务；如果对象是物流单元，再看教材列出的 SSCC 语境；如果要管理企业自己的资产，还要回到 GIAI 的资产管理定位。这个判断只说明“从哪类 GS1 典型场景开始看”，不替企业决定具体编码或申请流程。

[N008]
换一个问题：对象是否需要在供应商、制造企业和维护环节之间保持同一个身份？表 2-1 将 VAA 放在供应链和生命周期语境中，提示我们关注跨环节关联与企业内部细分；但具体结构和发码管理已经由第 15 集解释，本集不再重讲。

[N009]
如果主要对象是数字资产或网络资源，Handle 和 OID 的教材定位就更有参考价值。Handle 的对照语境是数字资产管理，OID 的对照语境是网络资源管理。它们在矩阵中的位置帮助我们先排除明显不匹配的候选，但不意味着一个对象不能在不同系统中同时拥有映射关系。

[N010]
Ecode 的对照语境覆盖物联网中的物流、仓储和生产制造。它的结构细节、版本段、体系标识和主码已经在第 18 集说明。这里保留的选型信息只有一条：当物联网对象需要在这些业务环境里被标准化表达时，应把 Ecode 放进候选集合，再核对企业已有编码和跨系统关系。

[N011]
所以，横向比较不能只问“哪一种最先进”，而要核对对象、主要业务、跨组织复用和内部系统延续这四项约束。四项都对得上，候选才有继续评估的意义。

[N012]
现实中，一个零部件可能同时参与贸易、物流、制造和售后。更稳妥的做法不是让一套编码承担全部语义，而是明确主身份、业务编码和映射关系。教材提醒，多体系兼容性不足；选型也要安排映射和数据关联责任。

[N013]
这也解释了教材为何提出需要兼容多体系的工业制造编码方案。这里是问题判断，不是本集发布的新标准；不能把五个示例拼成统一格式，也不能把 GTIN 结构套到其他体系。

[N014]
回到开头，五类编码怎么选，可以收束成四步：先确认对象，再确认主要业务场景；然后检查跨企业边界和内部细分，最后确认已有体系之间如何映射。GS1 在贸易流通中有清晰的教材定位，其他体系也各有典型语境；真正可落地的编码规则，要把这四步结果带到第 20 集继续设计。
