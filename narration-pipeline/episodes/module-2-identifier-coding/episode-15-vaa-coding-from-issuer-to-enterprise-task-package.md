## 2. Episode Positioning

- 主解释问题：一个企业内部的零部件或产品，怎样在 VAA 体系中获得既能被体系识别、又能由企业持续管理的身份？
- 一句话结论：VAA 把身份拆成发码机构代码、服务机构代码和企业内部编码三层，前两层提供可管理的体系位置，最后一层由企业按业务需要分配，从而让企业对象进入统一寻址范围而不丢失内部管理弹性。
- 纳入范围：VAA 的教材定义与授权链表述；中国信息通信研究院在教材中的发码、前缀分配与注册管理角色；《工业互联网标识解析 VAA 编码导则》及相关行业编码标准在教材中的位置；VAA 三段式结构；服务机构代码的国家、行业、企业三部分；企业内部编码由企业管理和分配；教材电池示例及生命周期管理语境；五种形式可映射转化的教材表述。
- 排除范围：VAA 当前授权状态、白皮书或行业标准的现行版本判断；Handle、OID、Ecode、GS1 的结构和横向选型；具体企业前缀申请操作、接口、注册平台页面、数据库、解析协议、条码/二维码载体、汽车动力电池 24 位规则的完整设计；企业编码字段、校验位和安全码的具体方案；任何学习者练习、测验或任务实施。
- 相邻分集边界：第 14 集只建立编码原则，不解释 VAA；第 16 集只解释 Handle 前缀/后缀和分布式解析；第 19 集才比较五类体系；第 20 集才讨论可落地的编码规则设计。本集的“示例”只用于解释层级关系，不是可注册编码或企业方案。

## 4. Content Type and Narrative Strategy

- 主类型：System mechanism（系统机制）。观众需要理解 VAA 三层身份结构和职责分工，重点是“谁提供体系位置、谁管理对象细分、三层怎样连接”，而不是背诵编码名称。
- 次类型：Design explanation（设计解释）。只用于把企业内部编码放回三层结构，解释企业为何仍有内部管理弹性；不进入规则设计、字段和长度。
- 本集叙事链：一件对象需要跨组织被识别 → 先确定发码机构与体系位置 → 再展开服务机构的国家/行业/企业层级 → 把最后一段交给企业内部编码 → 读取教材电池示例 → 说明五种形式可映射与生命周期语境 → 收束三层职责和证据边界。
- 问题闭合方式：先把“企业已有内部编号为什么还需要 VAA”具体化，再沿三层结构逐层回答；最后用同一个示例把层级、分隔和企业自治重新拼合，明确示例不等于现行注册方案。

## 6. Continuous Narration Master Script

以下 N001–N014 是本集唯一可录制口播文字来源。任何后续页面或分镜只能引用这些 ID，不得另写口播。

[N001]
想象一件新能源汽车电池离开生产企业，随后还要经过运输、销售、维护，甚至回收。每个环节都可能有自己的系统和编号。问题是：怎样让不同组织知道它们说的是同一个对象？VAA 编码的关键，不是再加一串孤立字符，而是把身份放进一个可管理的层级里。

[N002]
教材把 VAA 介绍为在我国工业互联网标识解析应用实践基础上发展起来的自主标识体系。教材还称，国际标准化组织、国际电工委员会和国际自动识别与移动技术协会授权中国信息通信研究院作为 VAA 的国际发码机构。这里我们按教材表述理解治理角色，不把它延伸成当前授权状态的判断。

[N003]
在这个角色中，中国信息通信研究院负责 VAA 标识的前缀分配与管理，提供编码规则的应用指导，并建立 VAA 标识注册管理平台。也就是说，企业不是随意拿一段字符开始编号，而是先进入一个有发码机构管理的体系位置。

[N004]
VAA 的基本结构可以先记成三段：发码机构代码、服务机构代码和企业内部编码。第一段回答“由哪个发码机构管理”，第二段回答“在什么国家、行业和企业层级中定位”，第三段才回答“企业内部具体是哪一个对象”。三段合在一起，才形成可继续关联的身份。

[N005]
先看第一段。教材中的示例把“VAA”写作发码机构代码。它不是某个产品型号，也不是企业自己随意选择的品牌缩写，而是整个编码结构的入口。把入口固定下来，后续的服务机构和企业编码才有共同的上级位置。

[N006]
第二段是服务机构代码。教材说明它可以由国家代码、行业代码和企业代码组成。示例中的“088”表示国家层级，“100”表示行业层级，“12345678”表示企业层级。这里要注意，示例帮助我们读懂层级，不代表所有行业都必须使用这些固定数字或固定长度。

[N007]
第三段是企业内部编码，由企业自行管理和分配。教材用某电池生产企业的内部编码举例，写成一个具体型号或对象的内部编号。企业可以把自己的产品、批次或其他对象区分开来，但本集只说明“由企业管理”的职责，不替企业设计字段、长度和校验规则。

[N008]
把三段放回一条编码中，就得到教材图 2-1 的阅读方法：前面是 VAA，接着是国家、行业和企业层级，最后通过分隔符连接企业内部编码。图中的字符串是教学示例；制作时应保留层级关系，不把它误读成可直接注册的真实编码。

[N009]
为什么要把企业内部编码单独留出来？因为统一体系和企业运营解决的是两类问题。统一的上层结构让跨企业、跨地域的记录知道对象属于哪个体系和企业；内部编码则让企业继续按自己的业务组织产品。两者连接，才兼顾唯一定位和实际使用的延续性。

[N010]
教材还指出，VAA 标识有五种形式，彼此之间可以映射转化。这句话的教学重点不是背出五个名称，而是理解同一个标识对象在不同应用场景下可以采用相容的表达。具体形式和转换规则，需要以当期导则和实际应用要求为准，本集不补写未给出的细节。

[N011]
把示例放回电池生命周期，就更容易看见它的价值：生产时记录企业内部对象，销售时沿服务机构层级寻找归属，维护和回收时仍围绕同一个身份关联记录。VAA 不是把所有业务数据塞进编码，而是为这些记录提供一个共同的身份锚点。

[N012]
教材提到，VAA 规则参照 ISO/IEC 15459 系列标准，并发布了 VAA 编码导则白皮书和若干行业编码标准。由于教材没有给出这些文件的现行版本，本集只把它们作为教材所述的规则依据，不在画面或口播中声称某一版本今天仍然有效。

[N013]
因此，读 VAA 编码时可以沿三步检查：先看发码机构代码，再看服务机构代码的国家、行业、企业层级，最后看企业内部编码如何区分具体对象。这个顺序既保护了体系治理边界，也避免把企业内部编号误认为全球层级代码。

[N014]
回到开头的问题，VAA 的作用可以浓缩为一句话：发码机构提供可管理的入口，服务机构代码提供层级位置，企业内部编码提供对象细分。三层共同构成跨环节可关联的身份；至于不同编码体系如何横向选择，我们留到后面的比较集再处理。
