## 2. Episode Positioning

- 主解释问题：对象已经有了唯一编码，查询者为什么不能只靠“读码”获得全部信息，标识解析体系又怎样把一个编码转化为可访问的信息或服务？
- 一句话结论：编码是对象的身份键，解析系统依据这个键在分层协作的节点体系中完成定位和查询，最终返回与对象关联的信息或访问入口；编码与解析缺一不可。
- 纳入范围：编码与解析系统的职责差异；DNS 类比的可用部分与边界；标识解析体系的两部分构成；国际根节点、国家顶级节点、二级节点、企业节点、递归解析节点的高层职责；从提交标识到获得相关信息的语义级查询路径；地址、位置、元数据等结果类型的教材示例。
- 排除范围：工业互联网标识的完整定义、私码问题与全生命周期价值；我国当前节点数量、城市布局、注册量、解析量和政策；VAA、Handle、OID、Ecode、GS1 的编码结构；前缀申请、标识注册、BMS/SNMS/ENMS 交互；正式递归解析协议与八步流程；节点内部组件、接口、缓存策略、数据字段、权限模型、性能指标和软件操作。
- 相邻分集边界：第 05 集回答“为什么要给对象统一身份”，本集只用一句承接“对象已有编码”；第 07 集回答“我国体系建设发展到什么阶段”，本集不引用教材中的 2024 年节点数据或政策目标；节点内部职责和具体注册、解析流程属标识数据管理与注册解析模块的责任范围，本集不展开。

## 4. Content Type and Narrative Strategy

- 主类型：System mechanism。观众需要理解的核心不是五个节点名称，而是一个标识查询为何需要编码、解析系统和分层角色共同工作。
- 次类型：无。DNS 对照只负责迁移已有认知，五类主体对照只负责解释机制中的分工，不形成独立比较结论。
- 本集叙事链：扫码后仍有信息问题的设想情境 → 编码与信息的边界 → 解析定义 → DNS 类比及边界 → 编码与解析两部分协作 → 一次查询的语义路径 → 五类主体的高层分工 → 结果与访问边界 → 稳定机制收束。
- 问题解决方式：先纠正“编码里装着全部信息”的误解，再用 DNS 建立“标识到结果”的映射直觉；随后沿一次查询逐步放入递归、顶级、二级和企业侧角色，最后用返回内容和动态边界校验理解，避免把层级图背成静态组织名单。

## 6. Continuous Narration Master Script

[N001]
上一集的收货现场里，共同标识已经让下游确认了“这是哪个零部件”。身份对齐之后，质检员还要继续追问：它属于哪个批次，当前状态怎样，相关说明去哪里查看？编码帮助我们确认查谁，却不会自动把这些信息全部呈现在眼前。读到身份，只是查询的起点。

[N002]
可以把编码理解为对象的身份键。它首先回答“这是谁”，帮助系统把一个对象同其他对象区分开。批次、位置、状态或说明等信息可以与这个身份关联，却不必全部写进编码本身。否则信息一变化，编码也要跟着改变，身份就失去了稳定的锚点。

[N003]
标识解析体系解决的，正是从身份键走向相关信息的问题。教材把它概括为：将设备、服务、产品等实体的标识符，解析为地址、位置、元数据等相关信息。这里的“解析”，不是把一串字符拆开读含义，而是让系统根据标识完成定位和查询。

[N004]
一个熟悉的类比是域名解析系统，也就是 DNS。人在浏览器里输入域名，系统会把便于识别的名称关联到网络访问所需的结果。工业互联网标识解析也有“提交标识、获得结果”的映射关系，因此教材用左右对照图帮助理解这种共同机制。

[N005]
但类比不能走得太远。DNS 主要帮助互联网访问定位，工业互联网面对的对象可能是设备、产品、零部件，也可能是算法、工序等虚拟资源；查询结果还可能关联地址、位置或元数据。两者共同点是解析映射，不代表协议、治理方式和返回内容完全相同。

[N006]
因此，教材把工业互联网标识解析体系分成两个相互配合的部分。第一部分是标识编码，为机器、产品、零部件以及虚拟资源赋予身份；第二部分是解析系统，利用这个身份进行唯一定位和信息查询。没有稳定编码，系统不知道查谁；只有编码，没有解析系统，也找不到它关联的信息。

[N007]
回到开头的零部件。质检员提交编码后，请求需要先进入一个可访问的查询入口，再由体系判断应当到哪里寻找相关记录。为了理解这个过程，本集只画一条语义路径：提交标识、找到负责范围、定位到企业侧相关信息或访问入口，再把结果返回给查询者。

[N008]
递归解析节点承担公共查询和访问入口的角色，并且可以利用缓存提升服务性能。它面向查询者接收问题，协助沿体系寻找答案。教材没有在这一节规定每次查询的固定协议步骤，所以这里不把缓存命中、转发顺序或返回字段编成一套操作流程。

[N009]
向上看，国际根节点面向全球范围提供根区数据管理和根解析服务。国家顶级节点与全球根节点互联，并支持跨二级节点以及异构标识解析体系之间的互联。它们解决的是更大范围内“应该向哪个体系、哪个服务范围继续寻找”的协同问题。

[N010]
二级节点更贴近行业，面向行业提供标识注册和解析服务。企业节点则服务特定工业企业，同样承担标识注册和解析，并可以结合企业特点定义数据访问方式。沿着高层职责理解，请求逐步缩小负责范围，最终关联到具体企业能够提供的信息或访问入口。

[N011]
把五类角色放回同一张图就会发现，它们不是五个彼此孤立的数据库。国际根和国家顶级负责更大范围的协同，二级节点连接行业服务，企业节点贴近对象及其数据，递归解析节点面向查询者提供入口。分层协作让查询能够在不同服务范围之间找到负责角色，而不要求查询者预先知道信息具体存放在哪里。

[N012]
查询返回什么，还要守住边界。教材列举了地址、位置、元数据等相关信息，企业节点也可以定义数据访问方式。这意味着，解析结果可能是信息，也可能是继续访问某项服务的入口；它不等于任何人扫码后都能无条件获得对象的全部生产、质量或商业数据。

[N013]
现在再看质检员的扫码动作：终端读出编码，编码充当身份键；查询入口接收请求，分层体系帮助定位负责范围；企业侧把身份关联到可提供的信息或访问方式；结果再返回到业务现场。这样，编码才从一串可识别字符，变成能够支撑信息查询的基础。

[N014]
本集讲的是稳定机制，而不是某一年建了多少节点、分布在哪些城市。具体布局、政策目标和规模数据会随时间变化，下一集再按发展阶段讨论。先记住这一条主线：编码回答“查谁”，解析回答“去哪里查、得到什么”，分层节点让这次查询能够跨范围协作。
