## 2. Episode Positioning

- 主解释问题：在主动标识服务架构中，为什么教材同时列出 SM1 和 SM2，它们分别承担什么安全角色？
- 一句话结论：SM1 和 SM2 都服务于主动标识的安全目标，但在架构上应分工理解：SM1 更适合承担数据机密性保护的对称加密角色，SM2 更适合承担身份鉴别、会话协商和签名等需要非对称密码能力的角色；本集只讲“放在哪里、解决什么协作问题”，不讲算法内部如何计算。
- 纳入范围：4.2.3“国密算法”段落对 SM1、SM2 的教材级角色描述；主动标识服务架构中终端设备、主动标识载体、安全认证服务、标识服务平台和业务云平台的关系；数据传输、身份认证、会话协商和应用构建之间的职责边界；对称/非对称角色的教学性比较。
- 排除范围：SM1/SM2 的数学原理、轮函数、曲线参数、算法强度、密钥生成/存储/交换步骤、具体密钥或证书值、接口字段、协议名称与配置、在线工具、代码、性能数据、合规结论、当前标准/产品状态、SM3/SM4/SM9 细节、行业部署量与政策目标、练习和测验。
- 相邻分集边界：第 39 集解释主动标识注册、上报和查询流程；第 40 集解释终端、载体、平台分层和通信/安全协作；第 42 集解释行业场景选择。本集不重复完整服务架构，也不提前展开行业应用。

## 4. Content Type and Narrative Strategy

- 主类型：Concept boundary（概念边界）。观众需要区分两个名称相近但职责不同的安全角色，而不是学会实现算法。
- 次类型：System mechanism（系统机制）。只用一条匿名数据上报链说明角色如何嵌入服务架构，不构造具体协议时序。
- 本集叙事链：业务安全问题 → 服务架构中的安全职责 → SM1 数据保护角色 → SM2 身份/会话协作角色 → 同一链路的分工比较 → 何时不能混为一谈 → 边界收束。
- 问题闭合方式：先回答“主动载体上报为何需要不止一种安全职责”，再分别放置 SM1/SM2 的角色，最后用角色对照和排除项避免把概念比较误读为密码学教程。

## 6. Continuous Narration Master Script

> 口播母版是唯一可录制文字来源；分镜只引用下列 N 段，不重写口播。以下段落不含制作指令。

[N001]
主动标识把设备身份和业务数据带进同一条链路，安全问题也随之变得具体：平台要知道“正在通信的主体是谁”，还要避免上报内容在传输过程中被无关主体读取或替换。教材在服务架构中同时列出 SM1 和 SM2，重点不是让我们背两个名称，而是看清它们分别靠近哪一种安全职责。

[N002]
先把位置放回主动标识服务架构。终端设备负责感知数据，主动标识载体与终端关联，再向上对接标识服务平台和业务云平台。架构图还列出安全认证、数据传输和应用构建这些职责。我们比较 SM1 和 SM2，正是要问：在这条服务链上，哪一类工作更像是在保护数据内容，哪一类工作更像是在确认通信参与者并协助建立安全会话。

[N003]
教材把 SM1 归为对称加密算法，主要用途是数据加密。对本集来说，只需要保留一个架构层结论：当主动载体向平台传送测量值、状态值或其他业务数据时，SM1 代表的是“把数据内容放进受保护通道”的角色。我们不在这里展开算法内部怎样分组、怎样计算，也不展示任何具体参数或密钥。

[N004]
因此，SM1 的观察入口是数据本身。它回答的是：已经确定要发送的内容，怎样在传输和存储环节得到机密性保护。这个角色可以落在主动载体的数据传输路径上，也可以由安全能力所在的芯片或设备部件承载；教材没有给出某个产品的固定部署位置，所以画面只保留“数据保护”这一职责，不把它写成接口调用或设备配置。

[N005]
SM2 的教材定位不同。它被描述为 ECC 椭圆曲线公钥密码算法，属于非对称密码，适用于数字签名、密钥交换等场景。这里的教学重点不是曲线公式，而是它更靠近“让通信双方确认身份、协助建立会话信任”的角色。也就是说，SM2 主要回答的是：这次通信的参与者能否被鉴别，后续会话能否在可信关系上建立。

[N006]
把一个匿名工业设备上报数据的情境放进来：平台先需要有办法确认载体和设备的身份关系，随后才有意义地接收一条需要保护的业务数据。这个先后只是帮助理解职责依赖，不是教材规定的接口时序。SM2 所代表的身份鉴别、会话协商或签名协作，与 SM1 所代表的数据内容保护，关注点不同但可以在同一服务链中配合。

[N007]
现在做一次并列比较。看“谁在确认主体”时，指向 SM2 的非对称密码角色；看“谁在保护内容”时，指向 SM1 的对称加密角色。看“认证服务”与“数据传输”两个架构职责，也能发现类似的分工：前者更接近身份和信任建立，后者更接近数据安全传送。这里是语义上的对应关系，不是说一个算法只能出现在一个模块里。

[N008]
这也解释了为什么不能用“谁更安全”来替代角色比较。SM1 和 SM2 解决的问题不同，不能拿一个笼统的优劣排序覆盖它们的职责；也不能看到 SM2 能用于会话协商，就把它扩写成完整的注册接口，更不能看到 SM1 用于数据加密，就虚构固定的数据格式。教材只给出了高层用途，我们就把结论停在高层用途。

[N009]
回到服务架构的对象关系：终端产生或感知数据，主动标识载体携带身份并承担连接，安全认证服务负责建立可被信任的通信关系，标识服务平台和业务云平台承接后续应用。SM1 与 SM2 是这条链路中的安全能力角色，不是新的业务节点，也不是替代平台的中心数据库。下游画图时，算法名称应贴在职责旁边，而不是画成凭空生成数据的黑盒。

[N010]
为了保持边界清楚，本集不把“安全性较高”“广泛应用”等教材泛化表述改写成当前部署数量、性能指标或合规证明；不引入 SM3、SM4、SM9 的算法教学；也不把教材中的任务实施网址、示例序列号、密文和工具界面带进画面。它们即使出现在原教材的后续操作段落，也不属于本集的角色解释。

[N011]
因此可以用一句话收束：SM1 代表主动标识链路中的数据内容保护角色，SM2 代表身份鉴别、会话协商和签名等非对称协作角色；两者共同服务于安全认证和数据传输，但不能互相替代，也不能被误读为一套完整的密码实现方案。

[N012]
当我们进入下一集的行业场景选择时，真正需要观察的不是算法名称本身，而是现场是否需要主动联网、身份确认、数据保护和更深的控制或查询。第 41 集到这里结束：保留 SM1 与 SM2 的职责边界，暂不延伸到密钥、接口、协议、参数、当前标准状态或具体行业部署。
