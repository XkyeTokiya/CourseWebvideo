## 2. Episode Positioning

- 主解释问题：同样都能把工业标识附着到对象表面，一维码与二维码为什么不能只凭“新旧”判断，应该怎样根据容量、识读动作和现场任务取舍？
- 一句话结论：一维码和二维码都是需要识读设备介入的被动标识载体；信息需求较简单、现有一维识读链可复用时，一维码可以保持方案简洁，信息密度和现场关联需求更高时可优先考虑二维码，但最终选择必须接受识读稳定性与实际环境验证。
- 纳入范围：标识编码作为对象身份编码的一句话自足背景（本集内交代，不展开编码规则与解析机制）；被动标识载体的共同边界；一维码沿一个方向表达信息的结构；二维码在二维平面记录信息及堆叠式、矩阵式两类结构；容量的定性比较；单码逐次识读的共同特征；扫码设备、手机和 PDA 等识读入口；生产、物料、质量和维护四类教材工业场景；容量、识读动作、现有设备和业务任务构成的基础决策路径；两类码的共同局限。
- 排除范围：任何码制的精确容量、尺寸、纠错等级、扫描距离、速度阈值、印刷精度和标准参数；EAN、UPC、GS1、ITF、PDF417、Code 49、Code 16K、QR Code、Data Matrix、Aztec Code 的详细规范；生成或展示承载真实数据的可读条码、二维码；RFID 原理与批量读取；材质、曲面、反光、油污、划伤、温湿度、化学环境和成本的完整选型；标签版式设计、在线生码、手机扫码操作和评分活动。
- 相邻分集边界：第 34 集独占 RFID 的标签、读写器、计算机系统与批量读取机制；第 35 集独占材质、制造工艺、表面状态、环境和成本驱动的完整选型；第 36 集独占尺寸、位置、耐久和信息层级设计。本集只在结尾指出这些约束需要后续验证，不展开解决方法。
- 保留/合并理由：确认版架构将一维码与二维码合并，因为相对容量、识读方式与使用任务只有放在同一选择框架下才有意义，分开讲会重复被动载体边界和低成本、需扫码等共同特征；同时隔离 RFID 和环境选型，才能在 6–8 分钟内完成一个清晰决策问题。

### 3.3 事实边界

- 受保护术语：被动标识载体、条形码（Bar Code）、条、空、二维码（Quick Response Code，QR Code）、堆叠式二维码、矩阵式二维码、扫描枪、手机、个人数字助理（Personal Digital Assistant，PDA）、生产管理、物料管理、质量管理、维护保养。
- 受保护比较：一维码沿一个方向表达信息；二维码在二维平面记录信息；教材只支持“二维码相对具有更高容量和可靠性”的定性结论，不支持本集给出跨码制统一的精确数值。
- 受保护共同边界：二者都属于被动标识载体，都需要识读设备介入，教材表 4-2 均表述为存储有限、一次读取一个标签内容、保密性低；不得把二维码说成联网载体、数据库或批量读取技术。
- 受保护场景：二维码的生产、物料、质量、维护和过程优化应用均按教材概括呈现；不发明字段、软件界面、实时指标、质量结果或自动控制动作。
- 可压缩内容：一维码的零售、图书、邮政、仓储物流应用可概括为成熟的逐件识读场景；二维码工业应用可压缩为生产、物料、质量、维护四组任务；具体码制名称只用于说明类型存在，不展开规范。
- 禁止跨章扩展：RFID 系统组成、非接触与批量读取原理；4.1.2 的材质、工艺、表面、污损和成本选型；4.1.3 的标签尺寸、位置与版式设计；任务实施中的在线工具、生码、真实标识串、手机小程序、扫码结果和考核评分。
- 补充来源用途：无。本集没有引入教材外的标准、参数、政策、产品状态或企业现状。
- 动态核验状态：`not verified—version unspecified`。具体码制标准和性能参数未核验，已全部排除；本集保留的结构、相对容量、被动识读和教材场景为稳定概念，不作 2026 年标准现状断言。

## 4. Content Type and Narrative Strategy

- 主类型：Comparison and selection（比较与选择）。观众最终应能依据任务约束做出有边界的初步选择，而不是记住“二维码一定优于一维码”。
- 次类型：Concept boundary（概念边界）。先建立二者共同属于被动标识载体，再用“一维方向/二维平面”解释容量差异从何而来。
- 本集叙事链：收货工位的选择问题 → 两类码的共同边界 → 一维结构与适用任务 → 二维结构与相对容量 → 容量比较 → 识读动作比较 → 四类工业任务 → 决策路径与现场验证 → 有边界的结论。
- 问题闭合方式：先排除“新技术替代旧技术”的单向判断，再用结构、容量、识读动作和任务需求组成比较矩阵；最后回到同一工业对象说明，选择的是适合现场的识读方案，不是单纯选择外观更复杂的图形。

## 6. Continuous Narration Master Script

以下 N001–N014 为本集唯一可录制口播文字来源。任何后续页面、分镜或备注只能引用这些 ID，不得另写第二份讲稿。

[N001]
在一个发动机零部件收货工位，同一件产品可以贴一维码，也可以贴二维码。两种方式都能让操作员扫码确认对象，但标签位置有限，现场已有设备也不同。真正的问题不是哪一种看起来更新，而是哪一种更适合这里要完成的识别任务。我们就从容量、识读和工业场景三条线来比较。

[N002]
先看共同边界。这里说的标识，指工业互联网标识编码，也就是一个对象在系统中的身份编码。一维码和二维码都属于被动标识载体，承载这段编码，通常附着在设备、物料、半成品或成品表面。它们本身不负责远程联网，需要扫描枪、手机或个人数字助理，也就是 PDA 等设备读取，再由后续系统处理标识。码面是对象入口，不是独立运行的信息系统。

[N003]
一维条形码只在一个方向表达信息。不同宽度和间隔的条与空形成可识读图形，用来表示数字、字符或符号。它的优势是成本低、标签容易制作、设备操作直接，因此在零售、图书、邮政和仓储物流等逐件识读场景中长期使用。

[N004]
一维码的边界也很清楚：教材指出它的数据容量有限，码面受损会影响使用，安全性也不足。因此，当任务只需要给对象一个相对简洁的标识入口，且现场已有一维识读设备时，它可以是一种简洁方案；但不能把更多信息需求硬塞进有限码面。

[N005]
二维码把信息分布到二维平面。教材把它分为堆叠式和矩阵式两类：堆叠式由多行短的一维码组合，矩阵式用黑白模块的平面分布编码。与一维码相比，二维码具有更高的容量和可靠性；其中矩阵式还具有更高的信息密度和更强的纠错能力。

[N006]
这里的比较只能是相对的。不同具体码制、尺寸和纠错设置会改变容量，教材没有给出可通用于所有情况的统一数值。所以本集不列“能存多少字符”的排行榜，只保留一个可用结论：当同一任务需要更高的信息密度时，二维码通常比一维码留出更大余量。

[N007]
容量更高，也不意味着应该把工艺参数、质量记录和维护历史全部写进码里。教材对被动标识载体的总体定位，是承载工业互联网标识编码，再通过识读和解析找到相关信息。把码作为稳定入口，通常比把不断变化的业务数据固化在码面上更容易维护。

[N008]
再看识读。教材表 4-2 把一维码和二维码都概括为一次读取一个标签内容，二者都需要设备对准具体码面完成采集。这一点与 RFID 的批量读取不同，后者留到下一集。这里选择一维还是二维，并不会消除逐件识读和读码设备介入的动作。

[N009]
二维码可由扫码设备、手机或 PDA 进入生产现场，但识读稳定性仍受条件影响。教材特别提醒，高速产线中的扫描速度和稳定性，以及光照、污染、表面损伤等因素，都可能造成失败或延误。二维码容量更高，不等于在任何现场都更容易读。

[N010]
一维码同样存在易受损的局限。于是，识读比较不能只看码的形状，还要看已有设备是否支持、操作员怎样对准、节拍是否允许逐件扫描，以及码面能否保持清晰。至于曲面、反光、油污、划伤和制造工艺怎样影响选择，将在第 35 集系统展开。

[N011]
把比较放回工业任务，第一类是生产管理。二维码可以附着在设备、原材料、半成品和成品上，支持任务领取与相关信息绑定。第二类是物料管理，通过扫码确认入库、出库、库存和上线投放位置。这里需要的不是“码越复杂越好”，而是对象身份与现场动作能够可靠对应。

[N012]
第三类是质量管理，操作员通过扫码关联质检结果和质量参数；第四类是维护保养，维护人员通过设备标识查找维护历史、保养日期和维修记录。二维码较高的信息密度适合这些关联任务，但真正的业务记录仍由后续系统管理，码面不替代质量或维护系统。

[N013]
因此可以用四步完成初选。先确定任务只需简洁身份入口，还是需要更高信息密度；再检查现场已有一维或二维识读设备；接着确认是逐件扫描，而不是批量读取；最后在真实光照、节拍和表面状态下验证。前两步帮助选择候选，后两步决定候选能不能落地。

[N014]
回到收货工位：信息需求简单、现有一维识读链可以复用时，一维码足以保持方案简洁；需要更高信息密度，并能稳定完成二维识读时，可以优先考虑二维码。但两者都受码面、设备和现场条件约束。选择的终点不是“哪种码更先进”，而是哪种方案能让对象身份被稳定、低成本地读出来。
