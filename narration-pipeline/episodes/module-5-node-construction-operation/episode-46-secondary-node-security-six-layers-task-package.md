## 2. Episode Positioning

- 主解释问题：二级节点的安全保障不是单个设备或一张检查表，而是哪些层面的连续责任？
- 一句话结论：按基础设施、网络、应用、数据、安全管理、物理和环境六层逐项建立防护与管理证据，才能把“提升综合安全防护能力”落实为可检查的安全面；六层内容按教材表述组织，不据此声称当前法规、等级保护或合规状态。
- 纳入范围：基础设施（主机、存储、云、身份认证与访问控制、防病毒）；网络与边界（安全域划分隔离、访问控制、机密性与完整性、异常监测、入侵防范、防 DDoS 攻击）；应用（访问控制、攻击防范、入侵防范、行为管控、协议安全、API 安全、用户/终端认证鉴别与唯一身份）；数据（分级分类、脱敏加密、完整性、备份恢复、安全销毁、按要求托管至国家顶级节点）；安全管理（制度、机构和人员、安全建设管理、安全运维、网络安全部门/专职人员/制度、应急预案、异常或突发事件及时上报）；自建机房才需要的物理和环境安全（物理访问、防盗窃和防破坏、防雷、防火、防水防潮、电磁防护、授权、出入登记、视频监控、线路与周边巡查、记录）。
- 排除范围：第 44 集的性能阈值、接口协议和部署资源；第 45 集运营方式、服务承诺、人员岗位数量和月度报备；标识载体模块的 SM1/SM2 算法角色；法规、等级保护级别、标准编号、当前主管部门要求、漏洞复现、攻击步骤、算法实现、产品或厂商合规状态。
- 相邻分集边界：第 44 集解决“节点能否稳定承载”；第 45 集解决“建成后如何持续运营”；本集解决“安全防护面如何覆盖”；第 47 集转入企业节点功能。

## 4. Content Type and Narrative Strategy

- 主类型：Construction and operations（建设与运营）。观众要能把“安全保障”拆成可盘点、可分工、可留证的六层，而不是记住抽象口号。
- 次类型：System mechanism（系统机制）。用覆盖关系说明六层如何共同保护节点服务，不画攻击路径。
- 本集叙事链：安全评审情境 → 基础设施身份与主机底座 → 网络边界与安全域 → 应用与身份行为 → 数据全生命周期 → 安全管理治理与上报 → 自建机房物理环境条件 → 六层证据清单与边界收束。
- 问题闭合方式：先建立“安全面不止一层”的问题，再逐层对应教材控制点，最后以部署条件和版本边界收束，说明安全是责任覆盖而非当前合规承诺。

## 6. Continuous Narration Master Script

以下 N001–N014 为本集唯一可录制口播文字来源。后续视觉节拍只引用这些 ID，不另写口播。

[N001]
假设一个二级节点准备接受安全评审。评审不能只问“有没有防火墙”，因为节点的安全面同时存在于基础设施、网络、应用、数据、管理和机房环境。本集按教材列出的六个层面建立责任地图，不作当前合规结论。

[N002]
第一层是基础设施安全。教材列出主机安全、存储安全、云安全、身份认证与访问控制、防病毒等内容。这里既要保护承载节点服务的基础设施，也要支持对企业节点和标识查询客户端进行身份认证、访问控制和权限管理。重点是先把“谁能接入、能访问什么”落到基础设施边界上，教材没有给出具体设备、账号体系或权限表。

[N003]
第二层是网络安全。二级节点要按业务特点划分不同安全域，在网络与边界之间建立必要的隔离和访问控制，同时关注通信的机密性与完整性、异常监测、入侵防范以及防 DDoS 攻击。教材还列出防火墙、入侵检测和入侵防御等技术手段。画面表达的是边界和防护面，不展开任何攻击步骤、漏洞或设备配置。

[N004]
第三层进入应用。标识解析系统及其应用需要覆盖访问控制、攻击防范、入侵防范、行为管控、协议安全和 API 安全。应用还要对用户和终端进行身份认证与鉴别，确保身份标识具有唯一性。换句话说，网络边界通过以后，具体应用仍要验证主体、约束行为并保护接口；教材并未提供 API 字段、算法或接口版本。

[N005]
第四层是数据安全。教材把数据分级分类、脱敏加密、完整性保护、数据备份恢复和安全销毁放在同一个生命周期里。二级节点还应具备数据备份能力，并按要求将数据托管至国家顶级节点，以支持节点安全稳定运行。这里不补写备份频率、恢复时间、密钥方案或托管现状，只保留数据从产生到退出的控制面。

[N006]
前四层说明“系统和数据怎样被保护”，第五层说明“谁来持续负责”。安全管理包括制度、机构和人员、安全建设与管理、安全运维，以及网络安全部门、专职人员、应急处置预案。异常或突发网络安全事件应及时上报相关主管部门；教材没有给出部门名称、时限或事件分级。

[N007]
第六层是物理和环境安全，但它有一个明确前提：二级节点自建机房时才需要单独考虑这一层。内容包括物理访问控制、防盗窃和防破坏、防雷击、防火、防水防潮以及电磁防护。机房还要有安全管理制度，控制区域访问授权、人员出入登记和视频监控，并定期巡查通信线路与周边环境，做好人员登记和巡查记录。

[N008]
把六层放在一张图上，可以看到它们不是从外到内的一条攻击路线，而是覆盖同一节点的六组责任。基础设施回答承载和权限，网络回答边界和隔离，应用回答身份与行为，数据回答生命周期，管理回答制度和响应，物理环境回答自建机房的现场条件。每层都要有对应的管理或技术证据，不能用某一个设备代替全部层面。

[N009]
六层之间存在依赖：基础设施和网络是应用控制的承载，身份与数据完整性支撑备份可信，制度、人员和预案承接异常处置；采用自建机房时，物理环境又是承载前提。这是教材条目的组织关系，不是事件因果推演。

[N010]
因此，安全评审可以围绕六个问题取证：基础设施身份权限、网络安全域和监测、应用主体认证与接口保护、数据分类到销毁、管理制度人员运维预案，以及自建机房的访问与巡查记录。这是取证框架，不是要求学员完成的检查表或练习。

[N011]
需要区分版本边界。教材引用《工业互联网标识解析二级节点建设导则（2021年）》并列出六层控制点，但本集未核验现行法规、等级保护、标准版本或检查口径。因此只说“教材要求”和“应覆盖”，不声称二〇二六年统一强制阈值或节点当前合规。

[N012]
本集不重复相邻内容：性能、接口和部署属第44集；运营、服务、岗位和月报属第45集；SM1、SM2 算法属标识载体模块的责任范围。这里只保留安全管理人员这一层面，不讨论数量、算法实现或运营 KPI。

[N013]
回到安全评审，答案不是再添一个孤立产品，而是把六层控制面和责任证据逐项对齐：基础设施、网络、应用、数据、安全管理，以及自建机房条件下的物理和环境。超出教材的字段、协议、漏洞、攻击路径、算法、阈值和当前状态，都应列入待核验清单。

[N014]
二级节点安全保障要做到“层面完整、责任清楚、证据可回查、版本不越界”。六层共同服务节点稳定运行；本集只解释教材结构，不替代法规评估、测试、演练或企业方案。下一集进入企业节点功能。
