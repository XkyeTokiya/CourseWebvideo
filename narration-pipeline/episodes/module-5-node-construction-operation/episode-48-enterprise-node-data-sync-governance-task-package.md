## 2. Episode Positioning

- 主解释问题：企业节点中的注册、业务、元数据、主数据和运行记录，如何在企业节点与上级节点之间保持可管理、可上报、可追溯的关系？
- 一句话结论：企业节点先保证注册与业务数据的正确、安全和维护，再通过核心/行业元数据形成主数据，并按教材列出的注册、统计、元数据、主数据、运行监测和业务数据路径向相应上级节点同步；同步是治理责任链，不等于一套已核验的接口实现。
- 纳入范围：5.2.2 的导语、标识注册管理、业务数据管理、元数据及元数据库、数据同步总则，以及六类同步内容的教材关系；企业节点、二级节点、国家顶级节点的上报方向和审核/转发边界；教学用 source-based synthesis/redraw 流程图。
- 排除范围：具体协议文本、接口字段、URL、数据库表、同步数值频率、冲突合并规则、质量指标、响应时延阈值、产品版本、IDHub 界面、部署命令、License、托管/自建和前缀申请入口；任何练习、测验、评分或操作演示。
- 相邻分集边界：完整数据概念、共享和标识数据模型属标识数据管理与注册解析模块的责任范围；第 47 集负责五项功能总览；本集只负责 5.2.2 的数据管理和同步责任，并在原有内容中最小交代主数据/元数据关系。第 49 集开始讲 IDHub 等运营产品，第 50–51 集讲建设与申请。

### 3.3 事实边界

- 受保护术语：标识注册数据、企业基本信息、企业标识前缀、业务用户信息、权限数据、解析服务数据、日志数据、核心元数据、行业元数据、主数据、标识统计数据、运行监测数据、统计类数据、异常报告类数据、二级节点、国家顶级节点。
- 受保护关系：注册数据正确/安全/更新；业务数据正确/安全/管理分析；元数据由上级节点同步并可扩展申请更新；主数据依据核心元数据形成；六类同步遵循教材所列协议和技术要求；变更注册信息经二级节点审核后向国家顶级节点同步；主数据存在直达国家顶级节点或经二级节点上报两条教材路径。
- 受保护限定语：注册信息“定期同步”、变更“实时申请提交”、统计“按要求上报”、异常“需及时上报”、业务数据“周期性上报”；这些词不转换成未提供的分钟、小时或批次频率。
- 可压缩内容：业务数据示例可合并为“用户、权限、解析服务和日志等”；统计数据只呈现注册量、解析量及分析结果；运行监测只呈现统计类与异常报告类两类。
- 禁止跨章扩展：标识数据管理与注册解析模块的完整数据概念定义；第47集五功能总览的重复讲解；第49集 IDHub 社区版/标准版、IDLink、License、产品能力；第50–51集托管/自建、安装、前缀申请；接口字段、URL、数据库表、冲突合并规则、质量指标、同步协议实现、当前产品能力。

## 4. Content Type and Narrative Strategy

- 主类型：System mechanism（系统机制）。观众需要理解数据对象、治理前提、同步方向和上级节点关系，而不是背诵六个名词。
- 次类型：Construction and operations（建设与运营）。用于说明企业节点要持续维护、上报和接受治理，不展开产品或建设操作。
- 本集叙事链：数据治理问题 → 注册/业务数据先保正确安全 → 元数据同步并形成主数据 → 六类同步按对象分流 → 二级节点审核/转发与国家顶级节点接收 → 运行报告闭环 → 明确未核验实现边界。
- 问题闭合方式：先说明“有数据不等于可治理”，再用一个匿名对象沿六类数据路径分流，最后把“数据内容、方向、责任”与“接口实现”分开，避免把教材关系误读为当前产品能力。

## 6. Continuous Narration Master Script

以下 N001–N014 为本集唯一可录制口播文字来源。后续分镜只能引用这些 ID，不得另写第二份讲稿。

[N001]
企业节点里有了标识注册和业务记录，还不代表数据已经能够被持续治理。企业要先保证注册、业务数据正确安全，再把元数据、主数据、统计和运行数据按责任同步到上级节点。本集沿一条匿名对象记录，回答数据怎样分层、怎样上报，以及哪些关系不能被接口想象替代。

[N002]
这里的匿名对象只是教学情境，不对应某家企业。它在企业节点留下注册信息，也产生用户、权限、解析服务和日志等业务数据。数据管理先确认记录可维护、可查询、可分析，把正确性和安全性作为同步前提。

[N003]
第一类前提是标识注册管理。企业节点要实时更新维护注册数据，并按要求向二级节点同步企业基本信息、企业标识前缀等更新信息。注册信息定期同步；发生变更时，实时向二级节点申请提交，二级节点审核后再向国家顶级节点同步。这里保留“定期”和“实时”，不补时间、字段或冲突规则。

[N004]
第二类前提是业务数据管理。它保障标识业务数据的正确、安全，并支持管理与分析。教材举出的范围包括用户信息、权限数据、解析服务数据和日志等。它们不是固定接口字段清单，方向和内容仍要遵循当期要求。

[N005]
接着看元数据和元数据库。企业节点从二级节点同步国家顶级节点发布的核心元数据和行业元数据，也可扩展行业元数据项并向两级节点申请更新。应用中，企业依据核心元数据填写对象属性值，形成主数据。元数据规定描述框架，主数据承载对象属性，两者不是同一层。

[N006]
有了治理前提，才进入数据同步总则。广泛同步是保证标识体系可用性的必要工作，企业节点应向二级节点同步注册、统计、元数据和主数据。具体要求遵循教材列出的对接协议和技术要求；本集只讲责任关系，不把协议名称转换成已核验的接口实现。

[N007]
第一组同步是注册和统计。注册数据沿“企业节点—二级节点—国家顶级节点”形成审核后的上行关系；统计数据按要求上报注册量、解析量及统计分析结果到二级节点。它们是教材列出的统计对象，不代表当前平台口径或质量达标线。

[N008]
第二组同步是元数据和主数据。企业节点与二级节点建立机制，更新核心和行业元数据。主数据可直接上报国家顶级节点，也可先到二级节点再上报；填报应按核心元数据格式。教材没有字段表、校验规则或冲突处理方式，画面只保留两条方向和这一格式边界。

[N009]
第三组同步是运行监测数据。企业节点向二级节点和国家顶级节点上报监测数据，分为统计类和异常报告类。统计类可包括注册和解析响应时延，异常报告说明系统异常并需及时上报。“及时”不改写成分钟数，也不添加告警等级或性能指标。

[N010]
第四组是业务数据同步。企业节点周期性向二级节点上报标识业务数据，主要是与标识应用相关的内容。“周期性”不等于本集可以规定日报、小时报或实时流；内容也不能扩写成未提供的字段集合。

[N011]
把六类同步放回治理图：注册关注身份和变更，统计关注注册量、解析量及分析结果，元数据关注描述框架，主数据关注对象属性，运行监测关注统计与异常，业务数据关注标识应用记录。对象和责任不同，但共同服务于标识体系可用性。

[N012]
这张图必须保留节点角色边界。二级节点不是无条件收进所有企业数据的总数据库；三类节点之间的接收、审核、转发，只按教材路径表达。接口字段、消息队列、重试策略、冲突合并和质量评分需要另有规范证据，本集不补写。

[N013]
检查企业节点数据治理可以沿四个问题进行：注册与业务数据是否正确安全地维护？核心和行业元数据是否有更新机制？主数据是否按核心元数据格式形成并走合适路径？统计、异常和业务数据是否按要求同步？这是教材责任复述，不是产品认证清单或当前能力判断。

[N014]
回到匿名对象，企业节点数据治理让身份、描述、属性、业务记录和运行状态在各自边界内可维护、可上报、可回查。第 47 集固定五项功能，本集补上同步责任；下一集进入 IDHub 等运营产品。我们只确认“同步什么、向谁、在什么教材限定下同步”，不虚构接口、频率或指标。
