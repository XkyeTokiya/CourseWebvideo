## 2. Episode Positioning

- 主解释问题：在标识解析分层体系中，国家顶级节点和企业节点各自处于什么位置、承担什么责任，二者怎样通过二级节点形成可理解的上下游边界？
- 一句话结论：顶级节点承担面向体系的枢纽、统一解析与备案核验等职责；企业节点属于企业信息系统，负责把企业内部系统和现场对象接入标识体系，并遵从上级节点的编码与管理规范。二者是不同层级的责任边界，不应把教材示意图直接当成 2026 年的节点部署现状。
- 纳入范围：3.2.1 顶级节点的体系定位、与根节点运行机构/标识注册管理机构的连接、全球/全国性解析与备案核验能力、图 3-18 三类系统；3.2.3 企业节点的企业信息系统属性、与二级节点和企业内部系统的双向对接、遵从规范体系、按企业规模在注册/解析基础上建立管理和应用服务、图 3-22 的层级和内部系统关系；二者角色对照。
- 排除范围：顶级节点“5 个主要节点+2 个灾备节点”的当前数量或部署现状；任何 2026 节点地图、可用性、性能、政策目标或规模统计；二级节点内部管理/功能/应用/安全架构（第 29 集）；企业节点五项功能、数据同步、IDHub、建设/托管选择和前缀申请（第 47–51 集）；接口、协议、字段、递归步骤、软件界面、业务案例和练习活动。
- 相邻分集边界：标识解析层级的总体认知属体系认知模块的责任范围，本集在模块内直接解释顶级与企业两端角色；第 29 集负责二级节点为什么承上启下及其内部组件；第 31 集负责递归解析请求路径；企业节点完整功能属节点建设与运营模块的责任范围。本集不提前承担这些机制的完整解释。

## 4. Content Type and Narrative Strategy

- 主类型：System mechanism（系统机制）。观众要理解节点层级中“谁负责体系级统一能力、谁负责企业内部接入和应用”的对象、关系与边界。
- 次类型：Concept boundary（概念边界）。用来区分教材示意结构、企业可按需求配置的系统，以及不应外推的现行部署事实。
- 本集叙事链：企业系统想让现场对象可解析 → 顶级节点提供体系级枢纽与统一能力 → 企业节点把企业系统和现场对象接入上级体系 → 两端通过二级节点形成规范边界 → 顶级与企业角色对照 → 回到教材图示的时间/版本边界。
- 问题闭合方式：先用同一对象的“上层解析”和“企业现场接入”两种需求建立张力，再分别解释顶级、企业职责，最后将二者放回分层链并声明图示不等于当前部署，从而避免把节点名称背成静态清单。

## 6. Continuous Narration Master Script

以下 N001–N014 为本集唯一可录制口播文字来源。任何后续分镜只能引用这些 ID，不得另写第二份讲稿。

[N001]
设想一件工厂现场的设备或产品。企业希望在自己的系统里管理它，跨企业查询时又希望能沿标识找到相关信息。要把这两个需求接到同一套体系里，首先要分清：哪些能力属于体系的顶层枢纽，哪些能力属于企业自己的节点？

[N002]
教材把国家顶级节点放在工业互联网标识解析体系的核心枢纽位置。它向上与根节点运行机构对接，面向体系提供全球标识解析服务；同时与标识注册管理机构对接，为异构标识的统一解析和注册信息的真实校验提供基础。这里讲的是责任位置，不是某个具体网站或软件界面。

[N003]
从服务范围看，国家顶级节点是中国范围内最上层的标识服务节点，教材描述它提供全国性的融合性顶级标识服务，以及标识备案、核验等管理能力。备案和核验强调的是体系层面的可信管理，和企业内部保存一条设备记录不是同一个层次的问题。

[N004]
教材还描述了五个主要节点和两个灾备节点，并列出相应城市。这些数字和城市属于教材叙述的节点布局，当前版本和实际运行状态没有在本集另行核验，所以只能作为教材背景，不作为二〇二六年的部署结论。

[N005]
图三点一八把顶级节点的系统构成归纳为三类能力：顶级节点智能分布式标识解析系统、工业互联网融合标识递归解析系统，以及工业互联网运行监测平台。教学上可以把它们理解为解析与管理、递归查询支撑、总体运行感知三条能力线；图中关系不应被改写成某个厂商的产品架构。

[N006]
现在把视线移到企业一侧。企业节点首先属于企业信息系统。它不是把企业从体系中隔离出来的一座孤岛，而是要向上与二级节点对接，向内与企业自己的业务系统和现场系统对接，形成一条从企业对象到标识服务的连接边界。

[N007]
这条边界还有规范约束。企业节点要遵从企业自身规定，也要遵从二级节点的编码规范、技术标准、管理规范和运营规范。也就是说，企业可以在自己的系统里组织业务，但不能因为拥有内部系统，就跳过上级节点定义的编码和接入规则。

[N008]
教材没有把所有企业都规定成同一种节点产品。由于企业规模和需求不同，企业可以在标识注册、标识解析等基础功能上，建立自己的管理方式和应用服务。这里的“可以”表示能力组合有弹性，不代表图中每一个 ERP、MES 或 WMS 都是所有企业的必选项。

[N009]
图三点二二给出一个更完整的关系视图：上方是根节点、国家顶级节点和二级节点，企业节点位于企业系统一侧；旁边还画出递归节点，企业节点内部则连接 ERP、MES、WMS 等业务系统，以及现场设备和采集终端。我们应把它读成角色关系图，而不是接口时序图。

[N010]
把两端放在一起对照，顶级节点关心的是体系级的统一解析、跨层连接、备案核验和运行感知；企业节点关心的是企业对象怎样注册、解析并和内部业务、现场采集发生关联。前者提供共同的上层锚点，后者把真实生产对象带进这套锚点。

[N011]
二级节点在这张对照里承担承上启下的规范边界：它连接国家顶级节点和企业节点，也为企业侧提供注册、解析及数据服务。本集只借它说明上下游关系，不展开二级节点内部的管理、功能、应用和安全架构，那是下一集的任务。

[N012]
因此，看到企业节点连接 ERP、MES、WMS 或现场终端时，不要马上推断某个企业已经部署了同样的系统，也不要把连接线解释为固定接口、实时同步或自动决策。教材图明确支持的是“企业节点与内部系统、现场对象存在对接关系”。

[N013]
用一句话收束：顶级节点负责把标识体系的统一性、可解析性和管理基础托起来；企业节点负责把企业内部对象、业务系统和现场采集接入这套体系，并在上级规范下形成自己的管理与应用。两者职责不同，才构成分层协作。

[N014]
接下来，第 29 集会解释二级节点为什么是承上启下的公共服务平台；企业节点的完整功能与建设运营由节点建设与运营模块负责。本集保留的检查框架只有三个问题：谁在提供体系级能力，谁在管理企业对象，图上的关系是否被误读成了当前部署事实。
