## 2. Episode Positioning

- 主解释问题：工业现场不断产生传感器、流程、供应链和外部信息，什么样的数据集合才称为工业大数据，它如何从采集走向可分析的价值？
- 一句话结论：工业大数据是覆盖设计、工艺、生产、管理和服务等环节的海量、多源、异构数据集合；通过采集、存储、治理和分析，把时序且强关联的现场记录转化为发现模式、改进产品、提升经营与生产效率的依据。
- 纳入范围：教材 3.1.1 对工业大数据的定义、结构化/半结构化/非结构化形态、覆盖环节、价值与产权属性；三类来源（生产经营业务系统、设备作业数据、外部数据）；一般大数据特征与工业数据的时序性、强关联性、准确性、闭环性；正文明确的采集—存储—分析处理链；从复杂数据集发现模式和知识，支持产品创新、经营管理、生产运作效率和新型商业模式。
- 排除范围：工业主数据、工业业务数据、元数据、数据字典的概念对照；数据共享制度、数据要素政策；具体标识数据模型、IDO 三要素、属性/事件字段；OpenAPI、HTTP、Apifox、节点注册与解析；任何企业规模、实时平台、算法、数据库、接口或收益数字。
- 相邻分集边界：第 22 集承接“数据类型如何区分”，本集只用“同一设备的多源记录”作教学情境，不给出主数据与业务数据定义；第 23–24 集展开共享和数据要素，本集只说明数据治理、交易、分析是价值环节，不讲制度；第 25 集展开标识数据模型，本集不设计对象属性或事件字段。

## 4. Content Type and Narrative Strategy

- 主类型：System mechanism。观众需要理解“来源如何进入处理链，再如何产生价值”，核心是对象、来源、数据流和结果的关系。
- 次类型：Concept boundary。只在开头和结尾划清“工业大数据”与后续主数据/模型课的责任边界。
- 叙事链：现场问题（数据很多但分散）→ 工业大数据定义与范围 → 三类来源 → 多种形态与工业特征 → 采集/存储/治理/分析处理链 → 模式与知识发现 → 产品、经营、生产和商业价值 → 边界收束。
- 问题解决方式：先把抽象名词锚定到匿名设备运行情境，再逐层增加来源、特征与处理关系，最后只用教材支持的价值方向收束，避免把“有数据”误解为“自动产生结论”。

## 6. Continuous Narration Master Script

[N001]
在一条生产线上，同一台设备会留下许多记录：传感器不断上报状态，生产系统保存工艺和订单，供应链系统记录物料流动，企业外部还可能有客户与供应商信息。记录越来越多，并不等于价值已经产生。真正的问题是：这些来源不同、格式不同、时间粒度也不同的数据，怎样被采集、保存、分析，最后支持工业决策？

[N002]
教材把这类数据集合称为工业大数据。它不是某一个软件里的数据，而是在工业活动中产生的海量、多源、异构数据集合，至少覆盖设备传感器、生产流程和供应链等对象。所谓“多源”，强调数据来自不同环节；所谓“异构”，强调它们的结构和表达方式并不相同。

[N003]
工业大数据既包括传统的结构化数据，也包括半结构化和非结构化数据。表格记录、设备传感器数据、日志文件，都可能成为工业数据的一部分。它的范围还会延展到设计、工艺、生产、管理和服务等环节，所以不能把它缩减成一张生产报表，或只看成某类设备的实时曲线。

[N004]
第一类来源是生产经营相关的业务数据。教材列举的来源包括企业资源计划系统 ERP、产品生命周期管理系统 PLM，以及供应链管理系统 SCM。它们记录企业在研发、生产经营和供应协同中的业务活动。这里的系统名称是教材中的来源举例，不代表本集要演示某个软件界面。

[N005]
第二类来源是设备作业数据，由生产设备和监测设备在物联网运行模式下产生，例如数控加工中的刀具负载、汽车零部件焊接数据、发动机拧紧数据，以及环境和温湿度数据。第三类是外部数据，例如客户名单、供应商名单。三类来源放在一起，工业大数据才有机会覆盖对象、过程和外部关系，而不是只保留单一环节的孤立记录。

[N006]
从一般大数据角度看，工业大数据具有数据量大、多样、快速和价值密度低等特征。价值密度低，意思是有价值的线索往往分散在大量记录中，不能因为数据多就直接得到答案。处理它需要先保留来源和上下文，再寻找可解释的关联。

[N007]
工业场景还强调时序性、强关联性、准确性和闭环性。时序性让我们知道记录发生在什么先后；强关联性把设备、工艺、物料和结果联系起来；准确性要求采集记录尽量可靠；闭环性则意味着分析结果能够回到产品、经营或生产运作中继续发挥作用。这些特征解释了工业数据为什么不能照搬一次性统计的处理方式。

[N008]
把来源和特征放在一起，就能看到一条基本处理链。数据首先需要通过物联网等技术采集，也可以由业务系统和外部渠道汇入；随后进行存储，保留必要的时间和对象上下文；再经过数据治理、数据交易或数据分析等价值环节。这里的“处理链”是对教材正文的教学组织，不虚构某个企业的数据库、接口或算法。

[N009]
处理链的重点不是把所有数据堆在一起，而是让不同来源的记录能够被整理、比较和分析。只有当设备作业、生产流程和供应链信息在相应语境中保持关联，分析才可能从复杂集合中识别出变化、关系和异常线索。至于采用哪种模型、阈值或平台，3.1.1 没有给出，本集不作补充。

[N010]
教材把工业大数据技术的目标概括为：从复杂的数据集中发现新的模式与知识，挖掘有价值的新信息。这个目标不是自动承诺某个结果，而是说明数据处理要服务于认识和改进。它把“记录”推进到“可解释的业务依据”，也为后续的数据共享和标识数据模型留下接口。

[N011]
在教材给出的价值方向中，工业大数据可以促进制造型企业的产品创新，提升经营水平和生产运作效率，并拓展新型商业模式。教材还指出，数据治理、数据交易和数据分析能够提升智能化水平、提高生产效率、降低成本并创造量化价值。这里保留的是价值方向，不补充金额、比例、企业名称或当前行业排名。

[N012]
所以，工业大数据的关键不只是“大”，而是来源广、形态多、与工业对象和过程保持关联，并经过采集、存储、治理和分析形成可用依据。本集先回答它从哪里来、怎样产生价值；下一集再区分业务数据、主数据、元数据等概念，后续课程才进入共享、数据要素和标识数据模型。这样，数据概念、处理机制与标识建模各自保持清晰边界。
