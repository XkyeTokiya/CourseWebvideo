## 2. Episode Positioning

- 主解释问题：二级节点为什么既连接国家顶级节点和企业节点，又能被称为公共服务平台；它提供哪些可回查的能力，哪些细节必须留到后续集？
- 一句话结论：二级节点向上对接国家顶级节点，向下为企业节点分配编码并提供注册、解析和标识数据服务，同时以管理、功能、应用和安全保障四个体系把行业级公共服务组织起来；它是承上启下的平台边界，不是集中保存所有企业数据的万能数据库，也不是当前产品或部署清单。
- 纳入范围：3.2.2 的定位和作用；行业型/综合型分类；总体架构的管理体系、功能体系、应用体系、安全保障四个部分；功能清单的高层语义；SNMS 与 IDIS 的角色分工；标识应用的支撑能力、推进路径和载体/领域分类。
- 排除范围：建设导则的现行版本判断、建设/部署模式、性能阈值、岗位与运营机制、安全六层细则（第 43–46 集）；注册页面、接口字段、Token、协议操作（第 26–27、30 集）；递归查询八步（第 31 集）；业务案例和任何当前节点数量、城市、平台产品或接口地址。
- 相邻分集边界：第 28 集说明二级节点在层级中位于顶级与企业之间，本集解释“平台为何承上启下”；第 30–32 集展开具体业务管理、递归和流程；导则中的建设与运营要求属节点建设与运营模块的责任范围。

## 4. Content Type and Narrative Strategy

- 主类型：System mechanism（系统机制）。观众要理解二级节点如何把上级互联、企业服务、功能系统和应用支撑组织成一个平台边界。
- 次类型：Concept boundary（概念边界）。用于区分公共服务平台的能力范围与“集中存储所有数据/当前产品清单”的误读。
- 本集叙事链：企业需要行业级标识服务 → 二级节点承上启下的两向连接 → 公共服务平台与规范管理职责 → 四体系架构 → 功能体系和 SNMS/IDIS 分工 → 应用支撑与分类 → 版本和实施边界收束。
- 问题闭合方式：先解释“为什么不能只靠顶级或企业节点”，再用定位、体系和组件证明平台角色，最后用后续集边界限制实施细节和动态推断。

## 6. Continuous Narration Master Script

以下 N001–N014 为本集唯一可录制口播文字来源。任何后续分镜只能引用这些 ID，不得另写第二份讲稿。

[N001]
上一集我们把国家顶级节点、二级节点和企业节点放回同一层级。现在问题更具体：企业为什么不能只面对顶级节点，或者各自建设孤立系统？因为行业里的标识注册、解析和数据服务，需要一个承接上级、服务企业的中间公共能力。

[N002]
教材把二级节点首先定义为重要的信息基础设施。它向上对接国家顶级节点，向下连接企业节点，并与递归节点协同，提供标识注册、标识解析和标识数据服务。这样，顶级节点的体系级能力才能沿着行业服务范围落到具体企业，而企业对象产生的标识服务请求也有明确的行业入口。

[N003]
二级节点还有第二个身份：公共服务平台。除了注册和解析，教材还列出应用支撑、微服务、工具模型、开发环境和规范接口，并在其上承载标识创新应用。“平台”不是集中收进所有企业数据的数据库，而是一组可被企业和应用调用的公共支撑。

[N004]
为了让这种公共服务可持续，二级节点承担标识规范管理职责。它要申请标识前缀，向企业节点分配下一级前缀，并结合服务行业制定编码、企业节点对接、接口和元数据等规范。规范的作用是让不同企业能够接入和交换，而不是替企业决定全部业务数据的内容。

[N005]
按服务范围，教材把二级节点分成行业型和综合型。行业型面向特定行业提供注册、解析和标识数据服务；综合型面向两个或两个以上行业大类提供同样的基础服务。这个分类只说明服务覆盖范围，不代表教材已经给出了某个行业或某个节点的当前数量。

[N006]
图三点一九把二级节点总体架构分成四个部分：管理体系、功能体系、应用体系和安全保障。它们分别回答规则、基础服务、应用支撑和安全运行问题，是责任分层，不是四个独立产品或固定机房。

[N007]
功能体系是平台能做什么的清单。教材列出标识注册、标识解析、标识查询、业务管理、数据管理、运行监测和系统管理。教学上可以把它们看成四组能力：先让标识能够注册，再提供解析和查询；随后管理业务与数据；最后对运行和系统本身进行管理。这里不展开每个功能的界面字段和操作步骤。

[N008]
再看图三点二零，二级节点功能架构由二级节点业务管理系统，也就是 SNMS，和二级节点智能分布式标识系统，也就是 IDIS，构成。SNMS 更接近用户交互和业务管理页面，IDIS 则以接口形式为 SNMS 以及上层应用提供标识注册、数据同步、解析和代理等核心支撑。一个面向管理，一个面向标识服务，两者共同组成平台能力。

[N009]
图三点二一给出一条语义级工作关系：标识注册子系统接收 SNMS 数据，处理后保存到标识数据中心，再由数据同步子系统交给标识解析子系统，对外响应终端查询。画面表达业务管理到解析服务的关系，不是某版本的接口时序、协议或性能承诺。

[N010]
公共服务平台的价值还在于应用体系。教材要求具备基础资源、数据和应用能力支撑，并提出与工业互联网平台协同、基于已有应用拓展、探索信息共享和数据安全等三条思路。因此二级节点不只提供注册接口，也为行业应用提供可复用支撑。

[N011]
在应用分类上，教材给出两个维度。按载体类型，可以分为被动标识载体和主动标识载体；按应用领域，可以分为公共标识应用和垂直行业标识应用。分类帮助我们理解平台服务的覆盖面，但不意味着本集要新增某个具体案例、设备清单或行业成效。

[N012]
把这些关系合在一起，二级节点的“承上启下”就清楚了：向上连接国家顶级节点，向下为企业节点提供前缀、注册、解析和数据服务，中间用四个体系组织公共能力。它连接的是服务责任和规范边界，不是接管企业全部业务系统。

[N013]
教材还引用了二〇一九年试行版和二〇二一年正式发布的《工业互联网标识解析二级节点建设导则》。这些日期用于说明教材依据和导则演进背景。当前适用版本、节点部署、接口协议、性能阈值和安全指标没有在本集另行核验，因此不能把教材框架直接说成二〇二六年的唯一实现。

[N014]
用一句话收束：二级节点之所以是公共服务平台，是因为它把上级互联、企业接入、规范管理、基础标识服务和行业应用支撑放在同一服务边界内。下一集拆解业务管理系统，后面再讲递归、流程和建设运营；本集不做操作演示。
