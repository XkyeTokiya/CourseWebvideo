## 2. Episode Positioning

- 主解释问题：在不暴露真实凭证和不依赖教材公网示例的前提下，如何用 Apifox 按当期接口文档调试“新增数据模板”接口，并判断一次请求是否完成了可核验的发送与响应检查？

## 4. Content Type and Narrative Strategy

- 主类型：Operational demonstration（操作演示）。观众应能复述并在授权环境中重建“准备—装配—发送—核对”的检查链，而不是背诵产品界面。
- 次类型：Concept boundary（概念边界）。用于区分稳定操作意图、教材示例与当前环境证据，防止将界面截图或 Token 当成教学事实。
- 本集叙事链：明确调试结果与授权前提 → 确认项目/文档和接口目标 → 选择调试模式 → 获取并脱敏 Token → 配置 Authorization 与 Content-Type → 按 schema 填写请求数据 → 发送并核对响应 → 保存可审计、无敏感信息的证据并收束边界。
- 问题闭合方式：先让“调试模板接口”成为一个受控任务，再逐步减少不确定性；每一步都以当期文档和授权环境为依据，最终只认可以文档解释的响应，不把发送按钮或绿色提示等界面信号当作业务成功证明。

## 6. Continuous Narration Master Script

以下 N001–N014 为本集唯一可录制口播文字来源。任何页面、分镜或制作备注只能引用这些 ID，不得另写第二份讲稿。

[N001]
这一集要完成一个很具体的操作目标：在授权测试环境中，用 Apifox 调试《二级节点 OpenAPI 接口》文档里的“新增数据模板”接口。这里的“完成”不是点到发送按钮，而是能够说明环境、身份、请求数据和响应证据分别来自哪里。

[N002]
教材把 Apifox 介绍为集 API 文档、API 调试、API Mock 和 API 自动化测试于一体的接口协作平台。对本集来说，它的角色是承载文档和请求调试；它不是二级节点服务，也不能替我们确认接口版本、字段或业务结果。

[N003]
开始前先做边界确认：只能使用获得授权的测试环境、当期接口文档和测试账号。教材中的公网地址、项目名称、示例参数、Token 以及截图都不作为本次操作输入。画面因此只保留环境名称的脱敏占位，不显示任何可用凭证。

[N004]
进入当期项目和接口管理页面后，先定位“新增数据模板”这一接口目标。界面可能随产品版本变化，教学上只关心这条关系：项目承载文档，接口条目承载方法和目标，调试模式承载一次可观察的请求。找不到接口时，应回到当期文档确认，而不是凭名称猜测。

[N005]
在新建或打开接口的页面，教材区分文档模式和调试模式。本集选择调试模式，是因为它允许在受控环境中装配并发送请求；模式名称、入口位置和按钮样式必须以当期 Apifox 页面为准，不能用一张虚构界面替代真实证据。

[N006]
发送模板请求前，先按授权身份接口获取 Token，并检查它属于当前环境。Token 只以脱敏占位进入画面和记录，不能复制教材里的字符串，也不能把“通常两小时”的教材说法当成当前服务承诺；有效期和刷新方式要回到当期文档确认。

[N007]
接着维护请求头。Authorization 按文档使用 Bearer、空格和 Token 的结构，作用是身份认证；Content-Type 按文档填写内容类型，教材通用说明给出 application/json 示例。两者职责不同，前者回答“谁在调用”，后者回答“主体怎样解释”。

[N008]
请求数据不能从截图或方法名推出来。打开当期接口文档的请求 schema，逐项确认字段、数据类型、必填关系和可能的唯一性约束，再在请求体中填入授权测试数据。教材发动机属性表只说明过建模思路，不提供本次环境可以直接提交的样例。

[N009]
装配完成后，先做一次静态检查：方法和目标是否来自同一接口条目，Authorization 是否指向当前环境的脱敏 Token，Content-Type 是否与文档一致，请求体是否通过 schema 检查。只要其中一项无法确认，就先回文档，不要把请求发送出去。

[N010]
确认无误后发送请求，并记录请求时间、环境标识和文档版本等非敏感上下文。响应区域只按当期文档检查定义的响应参数、结果或错误信息；不要因为界面出现绿色提示、耗时数字或某个状态码，就自动宣布模板已经创建成功。

[N011]
如果响应异常，先区分证据层次：是网络或环境问题，是认证失效，是请求体不符合 schema，还是接口文档与环境版本不一致。任务包不提供通用错误码清单；每一种判断都要回到授权环境日志和当期接口文档，不能用教材截图猜原因。

[N012]
如果响应符合文档定义，再保存脱敏后的请求和响应证据，去掉 Token、账号、地址、内部标识和业务敏感值。记录“使用了哪个文档版本、哪个测试环境、哪次请求”，这样别人复核的是操作依据，而不是一张无法追溯的成功截图。

[N013]
到这里，一次可审计的 Apifox 调试就闭合了：授权环境和接口文档先行，调试模式负责装配请求，认证头和内容类型各司其职，schema 约束请求数据，响应必须按文档解释。工具把动作集中起来，但不会替我们完成证据判断。

[N014]
本集不把教材示例地址、Token 或界面当成当前产品承诺，也不扩展到标识注册、递归解析或低代码集成。真正可复现的版本，应由下游在获得授权的测试环境中重新捕获；在没有这类证据时，流程图和脱敏占位比虚构软件画面更可靠。
