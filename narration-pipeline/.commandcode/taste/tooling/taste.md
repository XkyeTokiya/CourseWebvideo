# Tooling & Environment

- Shell syntax depends on which machine hosts the work: on the Windows box it is cmd.exe, not PowerShell or POSIX sh — use cmd syntax (`move /Y`, `dir /B`, `&`); PowerShell cmdlets (`Move-Item`, `$env:`) and sh constructs (`mv -f`, `tail`) fail there. But the 135-CourseWebvideo repo work runs on Linux/POSIX (/home/tokiya): `python3` heredocs (`<<'EOF'`), `&&` chains, `rm /tmp/...`, and `git -C` all succeed. Probe the environment before choosing syntax instead of assuming cmd.exe everywhere. Confidence: 0.85
- write_file is restricted to the workspace on the Windows box — writing to OS temp/scratchpad paths silently fails there; write drafts to an in-workspace temp filename (e.g., `*.new.md`) next to the target, validate, then atomically move onto the official path. On the Linux 135-CourseWebvideo host the tool-provided session scratchpad does work: EP07's narration-units freeze wrote and later edited a build+validate Python script under `/tmp/commandcode-1000/…/scratchpad/` and executed it successfully — prefer the scratchpad for throwaway build/verify scripts there so official folders stay clean. Confidence: 0.9
- When the user asks to commit ("提交修改"), survey `git status`/diff stat first, then stage and commit only the paths the current task actually modified (e.g., `player/episodes/episode-07/inputs` + that episode's `project.json`) — never sweep in unrelated or session-pre-existing changes (other episodes' files, settings/taste files). Name the intentionally-excluded paths in the wrap-up so the user can request them separately. Confidence: 0.7
- Git commits in 135-CourseWebvideo use Conventional-Commits form with Chinese text: `type(scope): 中文摘要` (e.g., `rebuild(episode-07): 口播、A-page 与 visual rough 无污染重建并替换正式产物`), followed by a Chinese bullet body and a `Co-authored-by: CommandCodeBot <noreply@commandcode.ai>` trailer. Confidence: 0.65
- Write large generated artifacts in segments (分段写入): when producing long output files (outline.md, script.md, bindings, previews), build them up via multiple sequential chunked writes instead of one monolithic write — long single writes are fragile (risk of truncation/timeout mid-artifact). User explicitly directed "分段写入输出文件" when resuming the stalled EP06 outline-first run. Confidence: 0.7
- 发布正式 inputs 走仓库自带工具而非手工拷文件：`narration-pipeline/scripts/publish_handoff.py --episode <ep> --source-dir <该期 .tmp 目录> --player-root <player>`，正式运行前先 `--dry-run` 确认清单与目标；`--player-root` 指向该期 `feature/episode-<NN>` 所在 worktree（inputs 是 Git 跟踪文件，必须在持有该分支的 worktree 里写入与提交），发布后逐文件 SHA-256 比对源与落位结果，并确认 compile trace 未混入 inputs。Confidence: 0.7
- Per-episode branch workflow: build each episode on its own `feature/episode-<NN>` branch created from the current main tip — never develop directly on `main`, and never recreate a branch that already exists (if it is checked out in another worktree, report that worktree's location and status instead). Switching/creating branches must not overwrite uncommitted user changes: count dirty files before, confirm they are preserved verbatim afterwards, and keep the `main` pointer untouched. Confidence: 0.9
- Stage prompts hand down absolute paths for the per-episode `.tmp/work/narration-pipeline/<episode-id>/` artifacts pointing at the MAIN repo checkout, and that is where stage outputs land; a separately created episode worktree (e.g. `01-CourseWebvideo-episode-11`) therefore keeps an empty `.tmp` and cannot see them. Before running a later stage inside the episode worktree, confirm which checkout owns `.tmp` (and flag the ambiguity as an environment note) instead of assuming the artifacts will be found. Confidence: 0.6
- When the current worktree carries uncommitted changes and a new per-episode branch must be created, the user prefers isolating it in a separate worktree (a sibling directory next to the repo, e.g. `01-CourseWebvideo-episode-11`) over switching branches in place, so the existing episode's dirty tree stays completely intact — offered as the safest option in a branch-handling question and chosen ("Good call — that keeps episode-08's tree fully intact"). Verify the source tree's `git status --porcelain` is byte-identical before/after and the `main` pointer untouched, and confirm the file tools can read/write inside the new worktree. Confidence: 0.7
- Never batch parallel edit_file calls against the same file: EP13's seven simultaneous edits to stage1-continuous-draft.md returned mutually contradictory snapshots (the same line reported in different states), signaling possible overwrite races. Apply multiple edits to one file sequentially, and after any batch of edits re-read the full file from disk to verify each edit's final state before reporting success. Confidence: 0.7
- Generator scripts that assign sequential IDs must emit them in final document order: Python evaluates call arguments before the callee, so constructing screen items inside `screen(...)`'s argument list gave every group item an ID before its page's title, failing the validator's strict S-sequence check (EP13-06). Pattern: build the title first, pass items as inert tuples, construct objects in an explicit order, and assert the emitted ID sequence is strictly increasing on a walk of the written JSON before invoking the official validator. Confidence: 0.6
- When executing a stage inside an episode worktree whose packet names main-repo skill paths, first `diff` the skill's SKILL.md between the main checkout and the worktree copy before trusting the loaded skill (done for `rewrite-course-narration` and `polish-stage1-narration` in EP13); flag divergence instead of silently following either copy. Confidence: 0.6
