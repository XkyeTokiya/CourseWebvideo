# Workflow
- Episode 生产流程:terse kickoff → 自助文档化(CLAUDE.md → production skill → 开工预检)→ 开工即把 project.json 翻到可预览态(合法取值与门控口径见 courseplay 分包;停在 planned 用户无法预览)→ 逐章交付报告(commit hash、绿勾清单含 audio:extract 分段数=outline 拍数、机制说明、逐拍节奏、待提供素材、验收指针、下一章预览)→ 用户"继续"放行;每章先在 entry.tsx 注册(import+chapters entry)并递增 project.json 完成数再跑链;章批次验证链一次通过后落地:`pnpm run episode:check && pnpm run typecheck && pnpm run lint && pnpm audio:extract -- --episode <ep> && pnpm run build`,随后带 Co-authored-by trailer 的 scoped commit。开发模式:Mode A(逐章制作·逐章确认)是长期默认,批处理节奏由用户在节奏 checkpoint 按运行指定,按所选立即执行并在统一验收节点停;多章批次:一次确认概述各章设计 → 同轮写完全部章文件 → 跑一次全链 → 单个合并 commit → 一份分章报告+共享验收指针;验证链被既有基线债(如 tools/ 既有 lint 报错)阻塞时,先按 git status/改动范围归因确认非本次引入,再单独跑其余环节确认交付物本身绿,基线债报告备案交用户裁决。Confidence: 0.8
- 完整制作任务的完成汇报结构(用户明示):制作完成后先做必要校验,再按固定四项汇报——修改或新增的文件、运行过的命令、校验结果、仍需人工处理的问题(待提供素材/未决项)。Confidence: 0.75
- 验收修订处理:用户"继续"放行时先把 outstanding 的用户指示验收修订落成独立 scoped commit,再开下一批;用户授权的编舞偏离按其规定的 step→element 映射原样实现,偏离点代码标注(如"本章偏离口播切分(Checkpoint 已授权)"),同步 outline 记录授权偏离及理由(仅本章豁免);用户指令的屏上文本删除:narrations/拍数逐字节不变,删 TSX 元素及整个 CSS 块(无死样式),同步 outline.md 所有提及处(章节块/步骤表/视觉调度表),记录"**用户修订(验收指示)**"来源行,被移语义归入既有内联元素不留洞,重跑 typecheck/lint 并重截图受影响状态。Confidence: 0.75
- Subagent 治理(以 episode-35 实证经验为准):正式制作由主线程完成,subagent 仅在用户明确选择并行开发模式时承接指定章节或承担只读审查;subagent 只报告——从不 git commit、不留持久 dev server,验证链与 commit 集中主线程;制作类交付后主线程重读交付文件并重跑全链,只读审查类抽查报告引用的文件与证据链,视觉验收归用户;交接契约未覆盖的机制级 taste 规则交付物仍会复发(ep35 实例:方向化延迟反模式)——交付复核除契约清单外按已知机制级规则批量自查;checkpoint 授权边界不因产出质量好而松动;agent 被中断后不从零重做——先盘点已落盘产物并逐文件核验完整性(narrations 完整、CSS 闭合、素材拷齐),把已完成/缺失/接续点写进重派 prompt 从缺口处继续;ep35 并行形态(首章主线程唯一风格锚、每 agent 2 章、prompt 内联消化规格+逐字 beat、agent 自跑 typecheck)已实证可复用。Confidence: 0.85
- Subagent 交接契约:整章构建交 general subagent 时交接必须完全自包含,且一律从交接时已提交工件引用、绝不凭记忆——冲突时已提交工件获胜(向它修实现,correction 记录在 commit/报告,修正契约带入后续章);必读清单:craft/reference docs、theme tokens.css、outline 章节块、已验收 sibling 代码为风格锚;冻结章契约:A-page id/recipe/关系机制、逐拍 narrations 原样复制、屏上文案不得改写、narrations.length 断言;硬规则清单(文件范围与注册、CSS 前缀、token-only、scene-pad 根、禁 setTimeout/emoji/假数据、动画≤口播)不在本条枚举,逐项从 craft 文档与 visual-design·courseplay 分包转录进 prompt;entry.tsx 一旦 import 未落盘的章文件,/play 动态导入整个 entry 即失败——立即摘除未落盘章的 import+注册项恢复可预览,agent 落盘后再注册回去。Confidence: 0.85
- 参考与教训:风格/模式挖掘只用 agent 自产工件,用户明确排除的 episodes 不作参考,用户提供的需求文件是绑定输入属另一类;当前 episode 缺的模式先 grep/read 自产 sibling episode 沿用而非发明;用户或审查在某章指出的验收缺陷,同轮主动自查后续章节同类模式并先修;必修缺陷跨章传播时先收齐全部审查报告再一次性修完、统一重验(区分"后续步骤填充的预留区"=设计意图 与 永久空区=缺陷)。Confidence: 0.8
- 脚本化验证:派生工件对照冻结输入用一次性脚本逐字对照(空白归一化、PASS/FAIL 行、mismatch 上下文),脚本进 scratchpad,以脚本证据替代肉眼比对;解析/抽取优先廉价确定性手段(如对枚举标记 grep)而非自然语言启发式,已验证的有损启发式只作交叉校验,绝不当锚点。Confidence: 0.8
- 被事实纠正后:以最细粒度重读文件重新计数,明确撤回错误结论、降级为可靠性风险、基于修正后事实重新推导建议;先弄清工件的结构惯例再做计数式验证,避免误报。Confidence: 0.8
- 风险试点与方案治理:风险性规则改动用沙盒试点把关(真实冻结输入、隔离在 tmp/、实现延后,按规则用证据审计出明确 pass/fail 并区分 blocking/non-blocking);契约层改动与下游再生成分开受控,延后范围写成显式 out-of-scope 条目而非静默丢弃;实现前逐条款反向对照实测/试点数据审计方案,分诊必修 bug/真实缺口/澄清并说明各修复是否影响已验证结果;绝不单方面改方案文件——给选项然后等。Confidence: 0.8
- Git 提交纪律:契约/治理改动落单个 scoped conventional commit,只 stage 明确任务路径(先查基线 `git branch --show-current && git status --short`);提交信息按影响取舍——行为/契约影响须全五件(背景动机、授权来源、逐文件映射、显式 non-goals、实验/回滚步骤),纯簿记/文字级至少动机+授权来源+逐文件映射,均带 Co-authored-by trailer;`.commandcode/taste` 的学习记录改动一并入库并推送远端,单独 `chore(taste)` commit 与功能提交分开。Confidence: 0.8
- 中断与暂停汇报:中断/恢复先给状态报告——轻中断(无未落盘写操作、无异常、无流程偏离)用三行短格式(已完成/确切中断点/下一步),有写操作、异常或流程偏离才用全序报告:已提交完成(含验收状态)→ 中断批次逐项表(状态+确切中断点)→ 明确未做事项 → 恢复后有序待办链 → 当前环境 → 交接提议;绿勾不等于完成,未提交/未审状态随行说明;"暂停任务"硬停按主文件交互条执行(零工具调用);证据化盘点(逐项 implemented vs placeholder、重跑验证链让"全绿"反映现实)只用于用户要求汇报状态或恢复生产前的环境确认("接续 <ep>+已完成阶段+请确认环境":git 基线与无关脏文件标注、冻结输入可解析性、产物↔冻结输入计数一致性、验证链结果、缺口待决项),确认磁盘工件完好后从确切步骤继续。Confidence: 0.75
- 流程不符被叫停的处置(区别于"暂停任务"全停):用户以"暂停制作+只允许只读操作"叫停并否定流程本身时,立即冻结一切写操作——含进行到一半的步骤,绝不为"把状态推进到合法"而继续写(冻结与编号裁决列表处置按主文件整体放权条),只读诊断/复盘可以继续;复盘按阶段分组、表格逐步骤细化(不要概要式时间线),每步标注[写]/[写-未完成]、失败尝试根因及授权来源(用户指令/taste 条款/skill 契约/validator 报错/我的自行判断),自行落盘显式标"我的自行判断,未请示"、taste 偏离单独标注,异常与未决项单列,末尾如实披露磁盘与验证链红/绿状态(宁可报红不粉饰)并附授权结构小结;结尾请用户指出不符环节,先只读诊断再等明确放行,不辩解、不按自己理解的流程推进。Confidence: 0.8
- 收官复盘(两种模式,不只失败后才复盘):管线测试收官的耗时复盘——按阶段分述各做了什么,耗时归因到具体摩擦源(协议冷启动、规则阅读配额、同步等审查、基线债挡路、must-fix 修复循环),对比批次间收敛度证明学习成本已摊销,附可执行降本方向(簿记工具化、参考压缩成 checklist、清基线债、审查异步化)供裁决,不做空泛致歉;经验固化复盘——把实证经验与硬边界教训整理成文档落项目 docs/(先看现有文档风格再动笔),组织视角听用户指定并按指定视角整份重写而非原地增补,内容组织为可复用资产(固定分段的 subagent 提示词模板、步骤化制作流程、按配方/构图类型归类的已验证手法与通用纪律),只收实际发生且验证过的经验,构想/推测一律排除或显式标注且不得当作经验陈述。Confidence: 0.7
- 设计与放权治理:没有好答案的设计张力先深入协作探讨(证据支撑的诊断:每个候选方案为何失败,锚定 skill 声明的哲学),不急于打补丁;开放设计问题在验证出新设计前不得编码进 contract/taste;放权保持窄、实验性、仅删除性——显式边界清单+显式关闭的未授予权力+恰好一条保守默认附加审查问题+每次行使自我文档化,失败一眼可检出、回滚平凡,试点后再谈扩展。Confidence: 0.85
- 非本会话所为的工作区改动:发现即先查 provenance(逐文件 git diff 定性),再验证其自带测试是否通过,然后以 A/B 处置选项交用户 checkpoint 裁决——绝不擅自回滚,也绝不把他人改动混入自己的提交;范围外缺口/基线债仅报告备案交用户裁决,不修、不并入当前 scoped commit,继续当前任务。Confidence: 0.8
- 工具/测试失败隔离复现:先跑配套测试定位失败用例,再在 tmp 沙盒用最小 fixture 复现(临时 cwd、逐项拷输入+theme、execFileSync 抓 stderr),逐输入二分根因——区分"代码坏/数据坏/工作区历史操作坏"并归因到具体提交;沙盒内引仓库工具一律绝对路径。Confidence: 0.6
- TTS 语音合成:音频属逐实例授权项(单次授权不外推为全局默认,不自动加语音);获授权后 `pnpm audio:extract -- --episode <ep>` 提取分段(段数=拍数,封面静默跳过)→ `pnpm audio:synthesize -- --episode <ep> --provider edge --voice <音色>` 合成(音色等参数逐实例指定);合成日志中的秒数是合成耗时不是音频时长——怀疑时长异常时用文件大小/实际工件核验,不按日志秒数判失败。Confidence: 0.75
- Taste 维护实证校验:taste 重构/新增后不假定注入生效——用户会要求用测试词开新会话验证核心条目是否体现(中文回复、先方案后动手、编号列表 checkpoint),分包跟随用领域问题验证(先读分包再作答),不跟随则把关键规则上提主文件。Confidence: 0.7
- Taste 修改先引原文:用户要求更改 taste 中某部分时,先逐字引用现有对应原文(所在文件+条目全文+Confidence)并等用户给出具体改法,再按指令落盘——不凭猜测直接改写条目。Confidence: 0.6
- 复盘对账 taste 的口径(用户明示):核对实际流程与 taste 条目时,定性为"冲突"而非"违反"——两侧皆合法、写明调和方向、逐项交用户裁决,不归咎追责;现行流程是较高优先级基准,从流程出发找张力点;用户会手动直接修改 taste 内容,对账/引用前先重读磁盘现状,不凭会话内旧认知。Confidence: 0.8
