# Workflow
- 脚本化验证:派生工件对照冻结输入用一次性脚本做逐字对照(空白归一化、PASS/FAIL 行、mismatch 上下文),脚本进 scratchpad——脚本证据替代肉眼比对;解析/抽取偏好廉价确定性手段(对枚举标记 grep)而非自然语言启发式,已被验证的有损启发式降级为交叉校验,绝不当锚点。Confidence: 0.8
- 被事实纠正后:以最细粒度重读文件重新计数,明确撤回错误结论、降级为可靠性风险、基于修正后事实重新推导建议;先弄清工件的结构惯例再做计数式验证,避免误报。Confidence: 0.8
- 方案与记录治理:风险性规则改动用沙盒试点把关(真实冻结输入、隔离在 tmp/、实现延后,按规则用证据审计成明确 pass/fail 结论,区分 blocking/non-blocking);契约层改动与下游再生成是分开的受控阶段,延后范围写成显式 out-of-scope 条目而非静默丢弃;实现前审计方案时逐条款反向对照实测/试点数据、分诊必修 bug/真实缺口/澄清、说明每个修复是否影响已验证结果,绝不单方面改方案文件——给选项然后等;契约/治理改动落成单个 scoped conventional commit,提交信息按影响取舍:行为/契约影响改动须全五件——背景动机、授权来源(谁在什么协商后授予什么)、逐文件改动映射、显式 non-goals、实验/回滚步骤;纯簿记/文字级改动至少动机+授权来源+逐文件映射;先查基线(`git branch --show-current && git status --short`)只 stage 明确任务路径。Confidence: 0.8
- 中断与暂停汇报:中断/恢复先给状态报告——轻中断(无未落盘写操作、无异常、无流程偏离)用短格式三行(已完成/确切中断点/下一步),有写操作、异常或流程偏离才按下方全序;确认磁盘工件完好后从确切步骤继续;用户以"接续 <episode> + 已完成阶段(如 p1)+ 请确认环境"恢复生产时,先交证据化环境确认(git 基线与无关脏文件标注、冻结输入可解析性、产物↔冻结输入计数一致性、episode:check 等验证链结果、缺口与待决项)再产出新内容;用户发起的暂停汇报必须基于证据——先盘点磁盘实际状态(逐项分类 implemented vs placeholder)并重跑验证链让"全绿"反映当前现实;报告按序:已提交完成(含验收状态)→ 中断批次逐项表(状态+确切中断点)→ 明确未做事项 → 恢复后的有序待办链 → 当前环境 → 交接提议;绿勾不等于完成,未提交/未审状态随行说明。Confidence: 0.75
- 流程不符被叫停的处置(区别于"暂停任务"的全停):用户以"暂停制作+只允许只读操作"叫停并否定流程本身时,立即冻结一切写操作——包括进行到一半的步骤(未落盘的登记、迁移后未补的验证),绝不为"把状态推进到合法"而继续写;只读诊断/复盘可以继续;复盘按阶段分组、表格逐步骤细化(用户明示要更细节、更条理,不要概要式时间线),每步标注[写]/[写-未完成]、失败尝试根因及授权来源(用户指令 / taste 条款 / skill 契约 / validator 报错 / 我的自行判断),自行落盘的写操作显式标"我的自行判断,未请示"、对 taste 条款的偏离单独标注偏离点,异常与未决项单列,末尾如实披露当前磁盘与验证链红/绿状态(宁可报红不粉饰)并附授权结构小结(用户直接授权 / taste·skill 流程内执行 / 自行判断落盘 / 条款偏离 / 待用户裁决);结尾请用户指出不符环节,先只读诊断再等明确放行,不辩解、不按自己理解的流程继续推进。Confidence: 0.8
- 测试收官复盘:用户把试点 episode 当作管线测试,测试结束/暂停时会要求过程耗时复盘——按阶段分述各做了什么(纯确认/必读/协议逆向/实现),耗时归因到具体摩擦源(协议冷启动、规则要求的阅读配额、同步等审查、基线债务挡路、must-fix 修复循环),对比批次间收敛度证明学习成本已摊销,并附具体可执行的降本方向(簿记工具化、参考压缩成 checklist、清基线债、审查异步化)供用户裁决,不做空泛致歉。Confidence: 0.7
- 参考与教训:风格/模式挖掘只用 agent 自己产出的工件,用户明确排除的 episodes(如 episode-03)不作参考;用户提供的需求文件(视觉粗设等)是绑定输入,属另一类;当前 episode 没有的模式先 grep/read 自产 sibling episode 的既有实现,沿用而非发明;用户或审查 subagent 在某章指出的验收缺陷,同轮主动自查后续章节同类模式并先修;必修缺陷跨章传播时先收齐全部审查报告再一次性修完、统一重验(区分"后续步骤会填充的预留区"=设计意图 与 永久空区=缺陷)。Confidence: 0.8
- 设计与放权治理:当前没有好答案的设计张力先深入协作探讨(证据支撑的诊断:每个候选方案为何失败,锚定 skill 声明的哲学),不急于打补丁;开放设计问题(如判断句载体)在验证出新设计前不得编码进 contract/taste;放权采用窄的、实验性的、仅删除性授权——显式边界清单 + 显式关闭的"未授予权力"清单 + 恰好一条保守默认的附加审查问题 + 每次行使自我文档化(显式字段+省略理由,语义保留为元数据) + 失败一眼可检出、回滚平凡 + 1-2 个 episode 试点后再谈扩展。Confidence: 0.85
- Episode 生产流程:terse kickoff → 自助文档化流程(CLAUDE.md → production skill → 开工预检)→ 逐章交付报告(commit hash、绿勾清单含 audio:extract 分段数=outline 拍数、机制说明、逐拍节奏、待提供素材、验收指针、下一章预览)→ 用户"继续"放行;每章先在 entry.tsx 注册(imports + chapters entry)并递增 project.json 完成数再跑链;章批次只在整个验证链一次通过后落地:`pnpm run episode:check && pnpm run typecheck && pnpm run lint && pnpm audio:extract -- --episode <ep> && pnpm run build`,随后带 Co-authored-by trailer 的 scoped commit。开发模式:Mode A(逐章制作·逐章确认)是长期默认,批处理节奏(每批几章)由用户在节奏 checkpoint 按运行指定,按所选立即执行并在统一验收节点停;多章批次:一次确认概述各章设计 → 同轮写完全部章文件 → 跑一次全链 → 单个合并 commit → 一份分章报告+共享验收指针。Confidence: 0.8
- 验收修订处理:用户"继续"放行时先把 outstanding 的用户指示验收修订落成独立 scoped commit,再开下一批;用户授权的编舞偏离按其规定的 step→element 映射原样实现,偏离点代码标注(如"本章偏离口播切分(Checkpoint 已授权)"),同步 outline 记录授权偏离及理由(仅本章豁免);用户指令的屏上文本删除:narrations/拍数逐字节不变,删 TSX 元素 AND 整个 CSS 块(无死样式),同步 outline.md 所有提及处(章节块/步骤表/视觉调度表),记录"**用户修订(验收指示)**"来源行,被移语义归入既有内联元素不留洞,重跑 typecheck/lint 并重截图受影响状态。Confidence: 0.75
- Taste 维护实证校验:taste 重构/新增后不假定注入生效——用户会要求用测试词开新会话验证核心条目是否体现(中文回复、先方案后动手、编号列表 checkpoint),分包跟随用领域问题验证(先读分包再作答),不跟随则把关键规则上提主文件。Confidence: 0.7
- Taste 修改先引原文:用户要求更改 taste 中某部分时,先逐字引用现有对应原文(所在文件+条目全文+Confidence)并等用户给出具体改法,再按指令落盘——不凭猜测直接改写条目。Confidence: 0.6
- Subagent 治理:模式 A(逐章制作·逐章确认)与模式 B(多章批处理)中严禁 subagent 直接执行实例制作——正式制作由主线程完成,subagent 仅在用户明确选择并行开发模式时承接指定章节或承担只读审查;整章构建交 general subagent 时,交接必须是完全自包含包(必读清单:craft/reference docs + theme tokens.css + outline 章节块 + 已验收 sibling 代码为风格锚;冻结章契约:A-page id/recipe/关系机制、逐拍 narrations 原样复制、屏上文案不得改写、accent 步规定组件形式与 narrations.length 断言;硬规则:精确新文件范围+仅 entry.tsx 注册、章唯一 CSS 前缀、token/primitive-only 无硬编码 hex/字体、scene-pad 根、无 setTimeout/emoji/假数据、字号下限、动画总时长≤口播长度;验证链+逐步截图后 playwright-cli close;固定报告格式);subagent 只报告——从不 git commit、不留持久 dev server,验证链与 commit 集中主线程(主线程独立复核按 subagent 类型分级——制作类:重读交付文件、重跑全链、playwright 自截图新章帧,provenance 写进提交信息;只读审查类:抽查报告引用的文件与证据链即可,不重跑全链、不截图;两类收尾都清理浏览器/端口),绝不把 subagent 自报告当完成证明转交;并行批:主线程预置共享/冻结层(目录+占位组件保持 entry.tsx 任何时刻有效、逐字预写全部 narrations、预复制素材、主线程注册),一个共享 dev server 禁止 agent 启停,每 agent 独立 playwright session(--session chN);交接契约必须从交接时的已提交工件引用,绝不凭记忆——冲突时已提交工件获胜(向它修实现、correction 记录在 commit/报告、修正契约带入后续章节)。Confidence: 0.85
- Subagent 模型与思考强度(用户明示):subagent 一律使用当前主模型,思考强度显式设为 low;若当前环境无法调整 subagent 思考强度,必须暂停并向用户报告,不得以默认强度继续派发——该条涉及模型资费,用户明示"必须如此"保留;语义强度审查时不得以"停机阈值与风险不成比例"为由提议弱化,模型资费优先于流程摩擦。Confidence: 0.9
- 中断 subagent 的接续纪律:agent 被中断后不从零重做——主线程先盘点其已落盘产物并逐文件核验完整性(如 narrations.ts 是否完整、CSS 是否闭合、素材是否拷齐),把"已完成/缺失/接续点"写进重派 prompt,让接任 agent 从缺口处继续。Confidence: 0.85
- 非本会话所为的工作区改动:发现即先查 provenance(逐文件 git diff 定性改动内容),再验证其自带测试是否通过,然后以 A/B 处置选项交用户 checkpoint 裁决——绝不擅自回滚,也绝不把他人改动混入自己的提交;范围外缺口/基线债的处置以用户裁决为准,用户明示"只关注当前 ep04 实例"后遵此执行:范围外项仅报告备案,不修、不并入当前 scoped commit,继续当前 episode 制作。Confidence: 0.8
- 工具/测试失败隔离复现:先跑配套测试定位失败用例,再在 tmp 沙盒用最小 fixture 复现(临时 cwd、逐项拷 episode 输入+theme、execFileSync 抓 stderr),逐 episode/逐输入二分根因——区分"代码坏/数据坏/工作区历史操作坏"并归因到具体提交(如恢复 commit 造成的记录哈希失配);沙盒内引仓库工具一律绝对路径。Confidence: 0.6
