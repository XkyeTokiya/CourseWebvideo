# Visual Design
- 系列视觉/代码惯例:相邻章不克隆构图(翻转朝向、变化 recurring bottom-bar 处理);内容承载优先自绘图示(SVG 自绘连线/管线/箱体/折线/汇聚图 + 流动或弹出动画),文字降级为图上小标注或正文短行——tag/chip 式罗列作为主要承载方式已被用户验收否决(用户原话"过度依赖 tag 式上屏内容"),不再用 word chips 承载关系;呈现层重做只换上屏形式,narrations 与 step/state 契约保持不变(不动内容源与状态机制);沿用既定 step-state 词汇(past/active/upcoming)与每章三件套模式(stateByStep 查找、boxed CSS 头注释、章唯一前缀、逐项 --i 交错延迟、narrations.ts);以既有章节代码为唯一真源。Confidence: 0.85
- 垂直构图:主内容/媒体区必须主导视口(~75-80% 高、垂直居中、撑满),短 takeaway 收缩为按内容最小需要的高度(实例参考 ~84px),按信息密度分配比例——主区 ~59% + 单句占下半页是被否决的形式;次级/语境卡锚定场景最底部,主视觉焦点居中偏上;收束落地时主构图轻微退让(可感知但轻微的 scale/opacity 下调,实例参考 ~0.985/~0.85)让位 takeaway。Confidence: 0.85
- 收束与判断条:结尾句以深色遮罩/蒙版呈现在媒体区上(scrim + 大字),不做独立底块;任何晚现元素(收束遮罩、底部提示行、第二问句)住在常驻预留槽/半透明占位里以 opacity 淡入,绝不条件挂载或回流;底部判断条不得抢焦点——有主导主区时收束条为紧凑居中、随内容收窄的条(主题面 tint + 细边框,无白卡填充/阴影,display 字号降档),或更强形式:收束与序列/轨道末项重合时省略独立底条,把末项样式化为阅读终点(is-endpoint)承载结论;视觉权重平衡是双向的——过轻的支撑内容按系列卡片语言提权(白/surface-2 填充 + navy 结构边框 + 硬偏移阴影、实心 accent 徽章、内容自适应 gap 流代替固定高);非对称双栏(主内容带+侧注列)侧栏显小时,再平衡要同时加宽栏宽(如 380→460px)并放大卡内字号/留白层级(如 56→72px、32→38px),不做单点微调。Confidence: 0.8
- 状态与动效:卡片状态切换必须真 cross-fade(ghost 槽标签与内容共存 DOM,经 opacity/visibility 过渡切换,内容加小延迟),背景/边框/阴影软时长过渡,绝不 display:none→block 硬切;步骤开场不得满屏元素——绑定本拍口播的支撑元素延迟进场(纯 CSS animation-delay 淡入,量级贴该拍口播节奏,实例参考 ~0.85s;主焦点块落地后才出),延迟纯 CSS 无 setTimeout,step 保持纯函数;跨章承接元素(并入组)进场即延续:直接以既定 past 态渲染(流程色表面),无入场动画,上一章预留虚线占位槽零重进场,仅新激活元素延迟进场;step 触发的编排动画必须门控在状态选择器下(如 [data-on="on"] .y{animation:...}),绝不在基础类无条件声明——否则动画在挂载隐藏期预播完,step 到达时观众只见硬切、核心演示从未到达观众(审查 must-fix 实例);配套:揭示过渡放元素本体、删失效后代过渡;stagger 仍贴该拍口播节奏但步长必须紧凑——秒级大步长级联被用户验收否决(用户原话"元素的动画间隔明显过长";实例:1.5-1.8s 步长、6.8-8s 才落关键元素的慢链),修复只压间隔/起拍、揭示顺序与状态门控结构不变,拍内全链在数秒内收完(实例参考:清单步长 0.6s、判据级联 0.45s、最宽定义级联 ≤1.2s、判断链 3.2-4.2s 内收完,既验证紧凑章步长 130-500ms)。Confidence: 0.85
- 揭示顺序服从口播推进:拍内关键句(判断注脚/落点句/强调变色)一律后置入场——纯 CSS delay 累算其前提/锚点元素级联完成时刻之后(如六 chips stagger 完 ~2s 则注脚 delay 2.2s、汇聚图稳定后落点句 delay 3s、变色延到摩擦 chips 就位后),绝不与前提同帧出现;delay 依据用内联注释标注,并列为每章制作自查项(A001 变色/A002 重组句曾被用户指出,A003/A004 起批量自查);条目进场的 step 归属须逐项对齐其口播句所属拍——某句是该拍末句时,条目应在**该拍 step 内收尾**出现,溢出到下一 step 才进场即门控缺陷(ep05 ch3 实例:"关联的记录未必找得到"按 outline 属第 2 拍末句,却被归到下一 step 进场,用户指"应在上个 step 的最后出现";此类 step 归属投诉先读 outline 本章设计块 + narrations 对账条目→拍映射定性,再查 CSS 进场 delay 编排定位溢出点)。Confidence: 0.8
- 反重复元原则(权威):反对的是"同一种信息组织方式被无差别地重复使用",不是反对某个具体结构——标题、底部判断条各自都是合法的(标题概念源自 skill 原初电影化定义);页面无固定跨页页头/页尾 chrome(kicker/报头/标题槽/底栏),标题/判断区是否存在与位置由当页构图决定,修复不得换名重引 chrome;判断句语义全页单一载体(同一信息每屏只渲染一次,含判断/总结句——一页不得双结论,收束/端点内容只在收束条表达一次);编码标准时禁止硬性表达层规格下限——把某种表达定为通用标准(如"标题必须 hero 级大字")会复刻"无差别重复",偏好形式无关的语义约束,强制决策落在拥有决策权的层;按形式而非按名判断(重复 13 页的顶栏 mark+h1 就是 chrome,不论叫不叫"论点标题")。Confidence: 0.9
- 内容纪律:范围边界句/元句("这里关注……不展开……")只进口播绝不上屏;production 内部术语(ghost/slot/"标题判断区")与制作约束句(CONSTRAINT/RULE)绝不作为屏上文案——屏上槽位文案一律取自 outline 的 sourced copy;图片/媒体占位槽保持轻量(比例框 + 短标签 M-id+标题 + 一行说明,不建复杂 SVG/动效演示);素材占位的取用/替换方式由用户统一安排,此处不预设具体形态。Confidence: 0.85
- 焦点主导与舞台契约:画面主导性体现在机制形状里——存在一个内容即锚的视觉主体(大数字/大图形/正在演示的机制)占据视觉中心,避免扁平等尺寸小卡仪表盘(小字、无焦点层级);每章必须有真实视觉演示——纯文字场景(标题+判断条+纯文本卡)是 outright 验收失败,草稿缺动效/图形元素就在交付前补齐体现口播关键词的语义视觉演示,优先沿用 sibling 章节已验证模式,新发明形式在交付报告说明理由;元素的结构存在 ≠ 达标,视觉执行本身是一阶验收因素(弱呈现拖垮整页);章根挂载 stage 契约(scene scene-pad),否则内容贴顶无舞台留白且被主题网格纹理压底;自定义全屏 scene 容器同受此约束——width/height 100% 铺满时必须自带 box-sizing:border-box + padding 消费主题 token 的舞台安全边距,内容绝不接触 1920×1080 画布边缘。Confidence: 0.85
- 卡片与代码红线:等重卡组共享统一内部骨架(kicker 顶部 / 主概念垂直居中 flex:1 / 底注锚定虚线上边框),无设计理由的兄弟卡结构分化即验收缺陷(确需分化须有信息层级理由并写入交付报告);"太空"卡靠全高内容分布+存在感解决(主项提权重如 36→40px display 900、长句拆标签 chip 行+虚线底注),不加新文案——"不加"指不造填充语;用户明示"结合初始 input 内容增补"时,增补材料=对照 a-page 对应 S 条目与口播原文找回被卡片丢掉的 sourced copy 原样恢复,仍不新造文案(ep05 实例:成立范围卡只落了 S007 后半句,补回前半句"私码是管用的"提为 40px display 主句、主题过程色强调);卡上"疑似缺信息"先对账冻结输入定性再动手——对账后内容完整即纯结构缺陷,只修结构零文案改动(ep05 定义卡实例:S006 两特征+命名已全部上屏,用户报"三横线两目"实为独立分隔线与条目自带底线重复,删冗余线+列表居中撑卡即毕);屏上 mono/注释标签字号设可读下限(1920×1080 画布实例参考 ≥20px);step 状态是 opaque token——用显式 Record<State,T> 查找,绝不当通用数组索引(states.indexOf(state) >= i 禁);idx>=i 门控下元素数不得超拍数否则尾部元素永不显示——元素组按拍映射(如 Math.floor(i/2) + 拍内交错 var),交付前逐拍走到最后一步确认全部到终态;waiting/占位槽复用共享 primitive 类时切到 [data-on="waiting"] 并显式重置 background/border/box-shadow 三件套(硬偏移阴影会渗到空占位上)。Confidence: 0.8
- 纵向留白分配:栏内条目列表夹在固定高元素与锚底收束块之间时,列表自身必须纵向弹性化(flex:1 + min-height:0 + space-evenly)把冗余空白均分进条目间距的呼吸里——“条目挤作一团(小 gap + 紧行高)+ 剩余空白单点堆积(列表与收束块之间大段死区)”同时出现即双重布局缺陷,用户明确两样都不要(ep05 ch4 侧注列表实例);多行条目行高 1.5 起步(1.4 显挤);弹性铺开时相邻固定区与收束块位置不动,只让列表内部消化空白。Confidence: 0.6
- 意外覆盖定性(用户把"晚拍元素盖住常驻内容"当验收缺陷报,原话"造成了不应出现的元素覆盖"):此类报障先查纵向预算溢出而不是 z-index/层级——预留槽型晚现元素(opacity:0 从首拍常驻 DOM、晚拍淡入上色显形)按完整尺寸全程占用列纵向预算,列内容合计超出卡内可用高度时 flex:1 居中区被双向挤压,溢出部分直到晚拍元素上色才显形为覆盖;修复=整列收回预算内(逐块小步收紧 padding/gap/演示槽尺寸/字号),以"任何一步都不再溢出"为口径,预留槽零回流机制不动。Confidence: 0.7
- 演示图形语义自解释:示意演示元素(演示槽/虚构示例字符)读不出含义时,用户会直接质疑其存在价值并问"这代表什么语义?能否删除"(ep05 ch6 ivn-risk-slot 实例)——收到此类语义/可删性问询,先对账 outline 本章设计块确认演示的存在依据,再给 保留+补锚点/删除/折中 选项交裁决;最终用户裁决:形状完全相同的示意槽即便补对象身份锚点(方案 B)也判"效果也不好",选保守删除(方案 A,原话"保守一点,选A")——差异化必须长在图形自身,完全相同的重复形状本身就是缺陷,文字标注救不了同质演示,修复选项中"删"优先于"加注补救";删除后纯文字面板被接受,"每章必有视觉演示"红线不阻拦用户明示裁决,张力在交付报告披露一次即可。Confidence: 0.75
