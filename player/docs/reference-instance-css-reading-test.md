# 不读取 CSS 的页面理解盲测

## 问题与方法

问题：后续制作参考实例时，如果不读取章节 CSS，能否理解页面结构和表现？本次对用户选定的五章各做一次对照，重点区分 DOM 内容结构、实际空间布局、逐步状态、视觉样式和动效。

| 组别 | 允许的材料 | 禁止的材料 |
| --- | --- | --- |
| A：源码盲测 | 五章 TSX、`narrations.ts` 和实例入口 | CSS、截图、网页、其他说明与运行时源码 |
| B：源码加画面 | 与 A 相同，另外查看一张五章最后状态的合成截图 | CSS、其他截图、网页和其他说明 |
| C：源码对照 | 五章 TSX、口播和 CSS | 不扩大到其他集 |

三个 subagent 分别独立作答；主 agent 再根据章节源码、CSS 和[最后状态合成截图](../../.tmp/validation/episode-design-reference/selection-20261028/overview.jpg)核对。截图是本地临时验证产物，只记录每章最后状态，不能直接证明前面各步或动画过程。各组都是一次受控测试，结果不是对不同模型、不同章节的统计结论。

## 结果

| 理解层面 | A：不看 CSS 和截图 | B：不看 CSS，增加最后状态截图 |
| --- | --- | --- |
| 内容与 DOM 层级 | 五章的主要内容块、嵌套关系都能列出。 | 同样能列出，并能把块对应到画面。 |
| 内容节拍 | 能从状态数组、条件和口播列出 3、3、4、4、3 共 17 个节拍的主要内容；视觉呈现仍可能误判。 | 节拍信息主要仍来自源码；一张末态截图不能验证之前各步。 |
| 空间布局 | 能根据命名和 DOM 作一些合理推测，SVG 自带的坐标可直接读取；但不能可靠确认完整页面的左右、上下与比例。 | 能观察五章最终画面的主要左右、上下关系，但仍出现一处卡片宽度误判。 |
| 颜色、字体层级、边框 | 除语义类名和少量内联属性外，不能确认实际样式。 | 能描述截图中的主要颜色、强调和边框；具体 CSS 数值及其他状态的样式仍未知。 |
| 动效和焦点迁移 | 能看到状态变化及少量内联坐标、自定义属性，不能据此确认大多数入场动作、时长、延迟与状态切换效果。 | 单张静态图仍无法还原动效过程；它只能显示一个结果。 |

### 两个具体误差

1. **06-03 的首拍占位**：A 根据状态判断首拍只有锚点。但 [TSX](../episodes/episode-design-reference/src/chapters/01-ep06-what-resolution-does/WhatResolutionDoes.tsx) 只是把关联区设为 `is-weak` 和 `aria-hidden`；[CSS](../episodes/episode-design-reference/src/chapters/01-ep06-what-resolution-does/WhatResolutionDoes.css) 实际让关联区以 `opacity: 0.38` 弱化显示，其中 chip 文字默认隐藏。因此首拍仍有弱化的关联组和空槽，不能从 `aria-hidden` 直接判断画面完全不可见。
2. **35-09 的卡片比例**：B 从最后状态截图正确判断四张卡横向排列，但认为它们近似等宽；[CSS](../episodes/episode-design-reference/src/chapters/03-ep35-route-validation/RouteValidation.css) 的列比例实际是 `1fr 1fr 1fr 2fr`，第四列明显更宽。截图帮助理解构图，但粗略观看仍可能看错比例。

### 不看 CSS 特别容易漏掉的动态设计

35-11 的 [TSX](../episodes/episode-design-reference/src/chapters/05-ep35-selection-conclusion/SelectionConclusion.tsx) 能看出最后一步增加 `is-pivoted`，但要读取 [CSS](../episodes/episode-design-reference/src/chapters/05-ep35-selection-conclusion/SelectionConclusion.css) 才能确认它使判断区变大、前面的回顾和结局弱化，并停止轨道光点。末态截图能看到结果，却不能单独说明这些变化在何时、如何发生。

## 阅读量参考

本次 A 组白名单中的实例入口、五章 TSX 和口播文件，按 `o200k_base` 对原始文件逐个计数，合计约 **8,365 token**。若再读取五章 CSS，合计约 **23,786 token**，差额为 **15,421 token**，约占后者的 **64.8%**。

这是文件原文只读取一次的估算，不是实际 subagent 的计费或完整任务消耗；它不包含截图的图片 token、文件路径和工具返回格式、额外说明、重复读取、输出或缓存影响。B 组查看了合成截图，因此不能用 A 组数字代表 B 组的实际总成本。

## 结论与使用边界

不读取 CSS，可以较好理解示例的内容组织和主要节拍；增加截图后，还能掌握最终画面的大体构图和视觉风格。但如果后续制作要借鉴占位、焦点迁移、进入顺序、状态过渡或精确布局，单靠 TSX 和一张末态图不够。

更适合进一步试验的读取方式是：先看章节索引与 TSX；需要构图时补看相应状态的截图；需要复用动态机制时补充简短的逐步表现说明或按需查阅对应 CSS。说明或截图能否以较低 token 替代 CSS，仍需实际制作并核算，不能由本次结构问答直接推断。
