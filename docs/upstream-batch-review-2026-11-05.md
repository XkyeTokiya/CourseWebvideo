建立日期：2026-11-05。范围覆盖现有课程各期的上游输入，优先处理 EP23、EP24 及与其同批发布的 EP22–32，然后处理仅有草稿的后续期次；已进入网页制作的期次单独核对，避免上游改动使已有页面与口播脱节。

用户已要求由 Agent 批量处理，不逐期要求用户审核。这里记录的是 Agent 的核对与处理依据，不把自动校验或既有 `approved` 字段记作用户逐期审阅。事实来源无法支持的内容不擅自补写；暂时无法安全处理的条目保持待核查。

## 执行顺序

1. 盘点正式输入、草稿、实际网页进度和报告版本。对已有正式输入重新运行适用的结构和完整性检查；报告只对应被验证的文件版本。
2. 逐期比对冻结任务包、当前口播、A-page 和视觉稿，处理已有内容审查指出的问题、事实边界、范围与相邻期重叠。检查结果及所作判断留在本记录或对应期的可追溯记录中。
3. 修正已发布内容时，同步受影响的口播、页面契约、视觉稿来源及验证报告；若已有下游计划或页面，先核对依赖并保留现有工作，不静默覆盖。
4. 对仅有口播草稿的期次，先核对草稿与内容义务，处理明确缺口；再按上游契约编译、设计视觉稿并验证。未完成整套验证的期次不标为下游可用。
5. 复查所有处理结果、文件摘要和仍存问题，给出每期实际恢复点。机器检查不代替语义审读，也不代表网页、音频或成片已经验收。
